# ArchCheck 项目汇报稿

## 一句话定位

**ArchCheck 是一个能“读懂”三维建筑信息模型（IFC）并依据中新两国规范自动生成合规报告的 AI 审查平台。**

它不仅代替人眼读图，更像一支分工明确、7x24 小时在线的**虚拟审图团队**：上传模型后，系统自动解析房间、结构、机电管线，逐条对照规范，最终输出一份带条文依据、可追溯的专家级审查报告。

打个比方：传统审图是人拿着尺子在电脑前一条条对规范；我们做的是给计算机一双**“能看懂 BIM 语义的眼睛”**，再配上一个**“记得住几百条规范、永远不知疲倦的审查员大脑”**。

---


### 1. 研究方向：为什么做这件事？

建筑设计必须严守大量强制性规范——疏散距离够不够、门宽是否达标、机电管线有没有冲突。传统人工审查工作量巨大，极易漏检，且规范更新时审查人员需要重新学习。与此同时，行业已普及 BIM（建筑信息模型），三维模型里天然包含了尺寸、材料、系统类型等机器可读的结构化数据。

我们的研究方向就是：**让 AI 直接读懂 BIM 模型，实现规范合规性的自动化审查**。

这里有一个关键的科学问题选择：我们**不追求**用大模型（LLM）直接做“黑盒判决”，而是坚持**“确定性规则引擎负责判、大模型只负责解释与协调”**的混合路线。因为规范审查容不得半点“幻觉”，必须保证每一条结论都可复现、可审计。

### 2. 研究内容：平台怎么做？

我们模拟真实审图团队的协作流程，设计了五个各司其职的 AI Agent：

1.  **BIM Reader（读图员）：** 负责解析 IFC 模型，精准提取楼层、房间面积、门宽、梁柱板截面。它还能基于房间邻接图和 Dijkstra 最短路算法计算疏散距离、构建管道网络拓扑。入库前先做“模型健康体检”，将空壳、无几何的劣质模型直接拦截。
2.  **Compliance Judge（审查官）：** 系统的核心，是一套确定性规则引擎。覆盖消防疏散、机电、电气、结构、全楼指标、无障碍六大专业，内置 47 条核心规则，支持中国 GB 55 系列与新加坡 Fire Code 2023 的一键切换。
3.  **KB Steward（知识库管理员）：** 基于 RAG 技术管理规范原文库（已入库 30 余份中新规范），并能将规范条文半自动转化为机器可执行的代码规则。
4.  **Reasoner（综合分析员）：** 利用大模型生成专业的审查叙述，协调跨专业冲突（例如当消防与结构冲突时，给出优先级建议）。
5.  **Independent Reviewer（复核员）：** 对每条判定进行独立复核，回溯检索规范原文，确保结论有据可依，留痕可查。

**工程上，我们最坚持的原则是“数据诚实”：**

如果模型里缺失关键字段（如照度、耐火等级等），系统会如实报告**“未检查，缺字段 X”**，宁可示弱，绝不默认通过。这与业界很多工具“查不到就当合格”的潜规则形成鲜明对比，也是我们建立审查信任的基石。

### 3. 作用与当前验证结果

平台的核心价值是将审查从“人工抽样式”升级为**“全量、秒级、每条都有依据”**。设计师送审前可自查，审查机构可辅助筛查，几分钟内输出问题清单、3D 标注图和标准报告。

最近，我们利用 **31 个真实 IFC 模型（含官方标准集、真实项目、机电模型，共 147MB）** 进行了实用性基线测试。结论如下：

*   **解析与性能已过关：** 18 层塔楼、单模型 2251 个机电实体均能全量读取。
*   **核心模型表现优异：** 7 个信息完整的真实建筑模型达到 S/A 级（得分 87–91）。
*   **诚实地暴露了瓶颈：** 约三分之一的规则在真实模型中显示“无数据可查”。这并非平台不会判，而是行业现状——BIM 建模端往往缺失这些属性。

下一步，我们将按照导师建议推进：**逐构件互检**（列出文件真值 vs 提取值，把准确率讲清楚）和**图形化可视校验**（在 3D 模型上直接点开构件看数据），把“读了很多”推进到“每一个都敢说读对了”。

## 专业锚点
| **技术栈** | **解析层：** `ifcopenshell` + `Python`<br>**算法层：** `networkx`（疏散图/拓扑）+ 混合几何（B-Rep）<br>**逻辑层：** 确定性规则引擎 + JSON 配置<br>**增强层：** `DeepSeek`（仅用于叙述、协调、规则生成）+ `RAG`（规范检索）<br>**前端层：** `Streamlit` |
| **为什么不全用大模型？** | 合规判定要求**零容错**、**可解释**、**可审计**。LLM 在逻辑推理上存在不可控的幻觉风险。我们的架构中，LLM 只负责“说人话”（解释结果）和“写代码”（辅助生成规则），判定逻辑 100% 由确定性代码执行，确保结果可复算。 |
| **规则从哪来？** | **来源：** 专家编写 JSON 规则包 + RAG 检索规范条文。<br>**生成：** 采用“人机回环”——LLM 起草规则草稿，经语法校验和人工确认后入库。<br>**扩展：** 加新标准只需增加一个配置文件夹，无需改动核心代码。 |
| **创新性在哪？** | ① **架构创新：** 角色化多 Agent 协作审查流水线；<br>② **信任机制：** 独创的“缺字段诚实上报”机制，拒绝默认通过；<br>③ **几何深度：** 基于真实几何（如 Dijkstra 疏散路径、B-Rep 截面）而非简单读表；<br>④ **跨域对标：** 实现中新双标准同构对比与一键切换；<br>⑤ **量化评测：** 建立了 31 模型九维量化评测体系。 |
| **局限（主动讲更稳）** | ① **几何近似：** 个别复杂字段（如变径管径）采用包围盒量取，存在近似误差；<br>② **数据依赖：** 稀有属性完全依赖建模端录入；<br>③ **解决路径：** 我们已规划“系统筛查疑似项 + 专家编辑器（EEE）确认”的人机闭环来弥补上述短板；真值互检机制也正在建设中。 |
