# ArchCheck 技术报告

> AI 多层建筑合规审查平台 — 多智能体架构 · 多标准切换 · BIM/IFC 输入
> 生成日期：2026-08-07

---

## 1. 项目概述

ArchCheck 是一个**面向多层建筑的规范合规自动审查平台**。核心价值：解决传统人工审图的两个盲区——① 每层单独看都合规、整栋汇总却超标；② 同一位置被两个专业同时标记、单专业审查看不到。系统用**多智能体架构** + **JSON 规则引擎** + **标准一键切换**实现自动化审查，并已支持**读入 BIM（IFC）文件**。

当前能力定位：**可运行的演示原型**（规则引擎 + 多智能体仿真 + 多标准 + BIM 结构解析均已打通；真实 LLM 接入与全自动房间提取为规划中的下一步）。

```
┌────────────────────────────────────────────────────────────┐
│  ① Web 界面层  app.py（Streamlit）                           │
│     上传与审查 · 审查结果 · 平台架构  （三页）                  │
└──────────────┬─────────────────────────────────────────────┘
               ▼
┌────────────────────────────────────────────────────────────┐
│  ② 核心引擎  core/（规则引擎 + 绘图 + 报告）                  │
│  engine.py   drawing.py   report.py   i18n.py   config.py   │
└──────────────┬─────────────────────────────────────────────┘
               ▼
┌────────────────────────────────────────────────────────────┐
│  ③ BIM 解析  bim/parser.py（ifcopenshell）   │  ④ 模型接口 llm/client.py（DeepSeek，骨架）  │
│  楼层/占地/门宽/构件 → 结构化数据             │  审查叙述 · 规则生成 · 协调器（规划）         │
└────────────────────────────────────────────────────────────┘
               ▼
┌────────────────────────────────────────────────────────────┐
```

**六个部分各司其职**：界面层负责交互，核心引擎负责"判定"，BIM 解析负责"读模型"，模型接口负责"推理/生成"（规划中），数据层承载规则，脚本负责生成演示资产。

## 3. 各部分详解

### 3.1 ① Web 界面层 — `app.py`（约 1030 行）

- **技术**：Streamlit（Web 框架）+ Pillow（图像处理）
- **三个页面**：
  1. **上传与审查**：上传 2D 图纸（PNG/JPG/PDF）或 **IFC (BIM) 文件**、加载三层演示数据、在线编辑建筑参数
  2. **审查结果**：统计卡片、标准切换差异面板、建筑剖面图、逐层 Before/After 标注图、四类问题 Tab、HTML 报告导出
  3. **平台架构**：四 Agent 说明、审查流水线、标准对比、技术栈、路线图
- **关键实现**：
  - **会话状态管理**（`st.session_state`）：跨页面保存审查结果、当前标准、当前楼层
  - **程序化页面跳转** `goto()`：解决 Streamlit widget 状态覆盖页面跳转的坑
  - **审查动画**：`st.status` + 分步日志模拟多智能体执行过程
  - **IFC 上传入口**：上传 → `bim/parser.py` 解析 → 显示结构摘要 → 房间参数编辑器补录
  - **双语界面**：中/英随所选标准自动切换

### 3.2 ② 核心引擎 — `core/`（约 1070 行）

| 模块 | 行数 | 职责 | 技术 |
|---|---|---|---|
| `engine.py` | 154 | **规则引擎 + 审查流程**：8 种操作符、条件过滤、四 Agent 执行、跨楼层聚合、冲突检测 | Python + JSON |
| `drawing.py` | 354 | **程序化绘图**：平面图、违规标注、修正图、建筑剖面图 | Pillow (PIL) |
| `report.py` | 112 | **HTML 报告生成**：内嵌图片 + 分页问题列表 | Python + HTML/CSS |
| `i18n.py` | 437 | **中英双语字典**（约 200 键 × 2）+ 语言切换 + 标签本地化 | Python dict |
| `config.py` | 13 | 路径常量 + 设计色板 | Python |

**规则引擎实现**（`engine.py`）：
- `run_rules()`：对每个规则做 `字段 → 操作符 → 阈值` 比对，支持 `<= >= > < == != in not_in` 8 种操作符和**条件字段过滤**（如"面积>50m² 才要求 ≥2 出口"）
- `run_full_review()`：**多智能体流程**——
  - Civil Agent：逐层跑消防规则（疏散距离/防火分区/出口数/门宽）
  - EEE Agent：逐层跑电气规则（应急照明/水源间距/回路负荷/插座覆盖）
  - Building Agent：整楼聚合校核（首层门宽/消防水池/变压器/应急电源）
  - Coordinator：按 `楼层::位置` 交叉索引，检测同层跨专业冲突
- `set_standard()` / `run_review_with_standard()`：标准加载与切换、跨标准对比审查

### 3.3 ③ BIM 解析 — `bim/parser.py`（约 171 行）

- **技术**：ifcopenshell（Python 的 IFC 解析库）+ numpy（矩阵变换）
- **能力**：
  - 读 IFC 文件 → 提取**楼层结构**（名称/标高/占地）
  - **门宽提取**：从类型名正则（如 "750×2000mm" → 0.75m）或几何回退
  - **构件统计**：墙/门/窗/柱/梁/楼板/楼梯数量
  - **单位换算**：IFC 常用毫米坐标 → 米
  - **对象身份处理**：用 `GlobalId` 而非对象引用做关联（ifcopenshell 不保证身份一致）
- **输出**：结构化建筑报告 + `build_review_data()` 合并房间模板生成引擎可消费的数据
- **已实测**：真实 IFC 文件（建筑四层.ifc：2 层/占地 5484m²/77 门；Snowdon Towers：18 层/155 空间）

### 3.4 ④ 模型接口 — `llm/client.py`（约 200 行，已实现）

- **技术**：anthropic SDK（Anthropic 协议）调用本地代理（`127.0.0.1:15721`，服务 DeepSeek 模型，`deepseek-v4-flash`）
- **定位**：**"模型负责读和说，规则引擎负责判"** —— LLM 只做推理/生成，不做数值判定
- **底层**：`chat()` —— 正确处理思考块/文本块；推理模型耗尽 token 时自动升级预算重试
- **已实现三个功能**：
  1. **审查报告叙述** `generate_review_narrative()`：规则引擎结果 → 自然语言专业审查报告（跟随当前语言，中/英）
  2. **冲突协调** `coordinate_conflicts()`：跨专业冲突 → 成因分析 + 协同处置顺序
  3. **规则自动生成** `generate_rules_from_code()`：规范条文 → JSON 规则（实测自动推断 code_ref）
- **App 集成**：结果页"🤖 AI 审查报告"折叠面板，点击按钮生成，结果存会话；代理不可用时优雅降级
- **已实测**：真实代理端到端（审查叙述 1308 字符 + 冲突协调 2166 字符，零异常）

### 3.5 ⑤ 数据与规则 — `data/`

- **规则**：按标准分目录（`standards/cn/`、`standards/sg/`），每套 3 个规则文件（civil/eee/building 各 4 条）+ meta.json
- **规则格式**：`{id, name, field, operator, threshold, severity, code_ref, message}`，支持条件字段
- **两套标准对比**（同一参数不同阈值）：

| 检查项 | 🇨🇳 中国 GB | 🇸🇬 新加坡 FC23 |
|---|---|---|
| 防火分区面积 | ≤ 2500 m² | ≤ 5000 m² |
| 回路负荷 | ≤ 16 A | ≤ 32 A |
| 插座间距 | ≤ 6 m | ≤ 10 m |
| 消防水池容积 | ≥ 216 m³ | ≥ 180 m³ |
| 应急电源时长 | ≥ 90 min | ≥ 60 min |

- **演示数据**：三层办公楼（每层 5 房间 + 2 防火分区），设计成"单层合规、整楼超标"

### 3.6 ⑥ 工具脚本与文档 — `scripts/` + `docs/`

| 脚本 | 用途 | 技术 |
|---|---|---|
| `generate_floor_plans.py` | 生成 CAD 风平面图 + AI 标注图 | Pillow |
| `generate_demo_ifc.py` | 生成带房间的演示 IFC | ifcopenshell |
| `generate_ppt.py` | 生成 11 页答辩 PPT | python-pptx |

**文档**：`docs/` 含 README、开发计划书、中英演示讲稿（md + pdf）

```
        │

  Civil Agent ──┐    （逐层）

  Building Agent   整楼聚合（首层门宽/水池/变压器/应急电源）
```

## 6. 当前能力边界（如实）

| 已实现 | 边界 / 未实现 |
|---|---|
| 多智能体架构（规则引擎驱动）| 合规判定为确定性规则引擎（LLM 不判数值，符合设计）|
| **DeepSeek LLM 层**：审查叙述 / 冲突协调 / 规则生成（已实现）| 各 Agent 由 LLM 驱动（Agent 化）未做 |
| CN GB / SG FC23 一键切换 | 仅两套标准 |
| 多楼层 + 跨楼层聚合 + 冲突检测 | 跨楼层为聚合计算，非 3D 竖向连续性 |
| BIM（IFC）结构解析 | 房间/面积未从几何自动提取（真实 IFC 常无房间语义），参数需补录 |
| 程序化平面图/标注/修正图 | 平面图为示意模板，非 CV 识别真实图纸 |
