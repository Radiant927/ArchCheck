# STR-002 规则工程逻辑决策请示

**呈报人**：ArchCheck 项目组　**日期**：2026-08-11

## 一、进展汇报

Phase 3.1「智能闭环」机制已交付：
- **KB Steward 已实现动态阈值查询**（基于 RAG + LLM 提取规范数值）；
- **审查引擎已支持模板化公式注入**（公式 → RAG/LLM → 静态回退三级解析，按规则+上下文缓存）；
- **实测跑通**：系统能够根据梁跨度动态计算审查阈值。

## 二、发现的技术局限（问题核心）

在落地 STR-002（梁截面高度）时，发现 **IFC 几何数据与结构设计意图存在偏差**，分两个层面：

### 层面一：框架梁比例（L/10）对住宅小梁偏严，造成误判

以 FZK 模型主梁为例（实际高度 **0.24m**，几何提取跨度 **4.08m**）：

| 判定逻辑 | 阈值 | 判定 |
|---|---|---|
| 框架梁 L/10 | 4.08/10 = **0.41m** | 0.24 < 0.41 → **违规（误判）** |
| 次梁 L/18 | 4.08/18 = **0.23m** | 0.24 ≥ 0.23 → **合规（符合实际）** |

### 层面二：几何全长 ≠ 结构设计跨度

以 FZK 檩条为例（实际高度 **0.16m**）：IFC 提取构件**全长 13m**，实际支座间距约 **4m**。

| 判定逻辑 | 阈值 | 判定 |
|---|---|---|
| 按全长 13m、L/10 | 13/10 = **1.30m** | 0.16 < 1.30 → **违规（几何数据噪音放大）** |
| 按支座间距 4m、L/18 | 4/18 = **0.22m** | 0.16 < 0.22 → **仍违规（真实，低于构造下限）** |

**小结**：主梁被 L/10 误判是核心误判；檩条 0.16m 无论采用哪种逻辑都低于构造下限，判其违规**正确**，恰能体现系统敏感性。

## 三、拟定的解决方案（三选一）

**方案 1：工程近似法（推荐）**
- 公式：**阈值 = max(0.20m, min(跨度, 6m) / 20)**
- 逻辑：构造下限 200mm（保证钢筋排布）+ 刚度校核按 L/20、跨度封顶 6m（修正几何全长过长）。
- 预期效果：
  - 主梁（0.24m）：min(4.08, 6)/20 = 0.204 → 阈值 0.204m → **通过 ✅**
  - 檩条（0.16m）：min(13, 6)/20 = 0.30 → 阈值 0.30m → **不通过 ❌（刚度校核，工程上正确）**
- 优点：逻辑严密、工程解释性强，能过滤几何数据噪音。

**方案 2：保守兜底法（最简单）**
- 公式：**阈值 = 0.20m**（静态构造下限）
- 预期效果：所有 ≥0.20m 的梁通过；檩条 0.16m 仍报错。
- 优点：报告干净、无争议；缺点：未利用动态能力，大跨度梁可能漏判。

**方案 3：严格合规法（风险高）**
- 公式：严格按提取跨度 **L/10**，不做封顶。
- 预期效果：大量长构件被判违规。
- 优点：完全基于模型数据；缺点：假阳性率高，演示需大量人工解释。

## 四、建议

建议采用 **方案 1**：
1. 主梁 0.24m 通过审查，**解决核心误判**；
2. 檩条 0.16m 违规是真实发现（低于任何构造下限），**证明系统敏感性**；
3. 展示"系统既有构造底线、又能按跨度动态变通"的专业形象。

## 五、需要确认的工程假设

方案 1 采用 **L/20 刚度比例** 与 **6m 跨度封顶** 作为工程近似值（针对住宅/次梁场景），并非某一规范条文直接给出的数值。若用于更广泛的项目类型，这两项假设需按实际工程场景复核调整。
