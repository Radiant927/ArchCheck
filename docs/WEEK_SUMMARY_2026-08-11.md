## 二、主线 1：数据真实化（机制细节）

### 2.1 IFC 解析与真实房间提取
- **解析**：`ifcopenshell.open` → 读取楼层 `IfcBuildingStorey`、空间 `IfcSpace`、构件。
- **楼层-空间关联**：通过 `IfcRelAggregates`（RelatingObject=楼层，RelatedObjects=空间）——**这是解析器识别空间的依据**（生成的 IFC 若用 IfcRelContainedInSpatialStructure 会解析不到房间，已踩坑）。
- **面积**：对每个空间用 `ifcgeom.create_shape` 曲面化 → 取 XY 投影的**凸包**（单调链算法）→ 鞋带公式算面积 × 尺度²。凸包对凹形空间会略高估（已知边界）。
- **单位推断**（`_length_scale`）：先读 `IfcUnitAssignment` 的长度单位；未声明时**从楼层标高推断**——真实建筑标高落在 0.5~500m → 米，否则按毫米。**Snowdon 正是"用米但没声明"，此机制解决了面积全为 0 的 bug。**

### 2.2 门宽真实提取（三级回退）
`_door_width_m`：
1. **属性**：`Pset_DoorCommon.OverallWidth`（Revit/ArchiCAD 常导出）→ × 尺度；
2. **名称**：正则匹配 `750×2000mm`（毫米）或 `36" x 84"`（英寸→×0.0254）；
3. **几何**：门包围盒水平较大跨度（FZK 门 0.885/1.01/2.01m 由此得到）。
任一失败返回 None → 引擎报"数据缺失"，**不编造门宽**。

### 2.3 门→房间关联
`_associate_doors`：
1. **精确路径**：`IfcRelSpaceBoundary`（RelatedBuildingElement 是 IfcDoor）→ 门挂到该空间；
2. **几何兜底**：门质心距房间凸包 ≤0.5m 且**同楼层**（避免跨层误配）→ 门挂到该房间。
两种路径合并去重。**无边界模型（Snowdon）靠几何兜底也能关联。**

### 2.4 真实疏散距离
`_compute_travel_distances`：
- 房间为节点、共享门的房间连边（边权=质心距离）→ networkx 图；
- **出口检测**：单房间门（外部开口）优先；无边界模型退到"门在外接框边缘"兜底；
- **Dijkstra 最短路**到最近出口 → `corridor_length_m`（替代默认 0，让 CIVIL-001 疏散距离规则吃到真数据）。
- 结果：FZK 3.6–5.7m，Snowdon 0–17.6m。

### 2.5 数据诚实化
- **无房间模型不编造**：仅跑整楼聚合 + 如实提示；
- **房间类型 `_classify_room_type`**：关键词匹配（Stair/Corridor/Meeting/Equipment/Vestibule/Office）→ 无匹配标 **`Unknown`**（不猜 Office），配中性色；
- **参数来源标注**：参数编辑器 🟢来自模型（面积/门宽/出口/疏散/楼层）/ 🟠默认·待填写（水池/变压器/应急电源/照明/水源/负荷/插座）；
- **去假数据回退**：未上传时参数编辑器不显示 demo 假数据，提示"请先上传 IFC"。

- **付费索引**：SS EN Eurocodes、SS 638/563/575/551/531/530、GB 50016/50974/51309/50116/50054/50055/50010/50017/50011/50009 —— 只登记标准号/名称/范围，**不收全文**。

### 3.2 免费规范落盘 + OCR
- 11 份免费文档落盘 `data/rag_kb/`（已 gitignore）；Fire Code 2023（20.6MB）、GB 55037（66 页扫描版，**用 RapidOCR 转出 36,921 字符可检索文本**）、GB 55036（自带文字层）。
- 工具：`sso_html_to_txt.py`（SSO 法规 → 文本）、`ocr_pdf.py`（扫描 PDF → 文本）。

### 3.3 关键事实修正（靠真实文档核对）
- **GB 55 免费全文在住建部/gov.cn 政策库**，不在 openstd.samr.gov.cn（那是国家标准库，不覆盖工程建设规范）；
- **GB 55037/55036 已取代** GB 50016/51309/50974/50116 等的强制条文；
- CP 5 → **SS 638:2018**；SG 应急照明应为 **SS 563**（原误引 SS 551，SS 551 是接地规范）。

### 3.4 清洗工具（`cleaning_rules.py`）
- 检查 CP 5、GB 50045、SS 551 误用、GB 55037 错误年份等过期/错误引用；
- **窗口化 ±80 字符**匹配上下文（避免整篇误报）、词边界（避免 CP 5 误伤 CP 52/55）、跳过 "Formerly CP 5"、pypdf 直扫 PDF；
- 验证：官方文档扫描 **0 错误**，项目规则扫描精确命中 **5 个真错误**。

### 3.5 付费标准处理
- 不下载、不破解，只建索引；规则引用付费标准**不写条款号**（无法核实）；
- 审查遇付费标准 → 标注"**请查阅原文**"（数据合规亮点）。

## 四、主线 3：架构演进（机制细节）

### 4.1 5 角色 Agent
| Agent | 职责 | 代码 |
|---|---|---|
| ① BIM Reader | IFC 解析 + 模型可用性 QA（健康度 0-100，致命阻断） | `bim/parser.py` + `extractor.py` + `qa_validator.py` |
| ② Compliance Judge | 确定性判定（消防/电气/结构/无障碍，按房间/构件/整楼对象） | `core/engine.py` |
| ③ KB Steward | 规范库 RAG、动态阈值、规则生成 | `kb/steward.py` + `data/rag_kb/` |
| ④ Reasoner | LLM 叙述/冲突协调/规则生成 | `llm/client.py` |
| ⑤ Independent Reviewer | 规范原文复核（**显示已从结果页移除**，概念保留） | `agents/reviewer.py` |

### 4.2 判定引擎（`run_rules`）
- 规则 JSON：`{field, operator, threshold, condition_field, code_ref, message}`；
- 逐条比对：`字段值 OPERATOR 阈值`（8 操作符）；字段 None → "数据缺失"（不崩不假过）；
- 按**房间**（civil/eee）、**构件**（structural，如 STR-001 柱截面≥0.3m）、**整楼参数**（building）三类对象跑；
- **标准配置化**：`engine.list_standards()` 扫描 `data/standards/*/`，加新标准=丢文件夹。

### 4.3 动态阈值（`kb/steward.resolve_threshold`）
- 规则可带 `dynamic_threshold`：**公式 → LLM 提取 → 静态回退**，按 (规则,上下文) 缓存；
- 例：STR-002 梁高 `max(0.2, min(span_m, 6)/20)`——主梁 0.24m 通过（阈值 0.204）、檩条 0.16m 报（阈值 0.30）；
- 公式占位符先替换再 eval（修复了 `{span}` 变集合字面量的 bug）。

### 4.4 独立复核为何从 UI 移除
- 复核=拿 code_ref 去免费语料检索，命中"已复核+证据"，否则"待人工复核"；
- 现实：演示规则大量引用**付费标准**（GB 500xx/SS 638），语料没有 → 全部"待人工"、信任度 0% → 显示出来像坏了；
- 处理：**从结果页移除复核显示**（徽章/统计/复核区/说明），概念保留在架构页与代码，单独向老师讲。

### 4.5 结果页 V2.1
- 双栏（左判定列表带专业标签 / 右平面图）、3D 等轴视图、筛选器、④ AI 报告移到底部；
- 修复跨块 `st.markdown('<div>')` 渲染成文本的 bug（改 `st.container(border=True)`）；
- 卡片内联样式抽成 CSS class（`.card-title/.tag-disc-*/.tag-sev-*`）。
