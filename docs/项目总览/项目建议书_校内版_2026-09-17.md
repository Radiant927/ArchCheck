# 项目建议书

# ArchCheck：从 BIM 智能审图到建筑全生命周期预测性合规平台

> 关键词：BIM+AI 智能审查 · 规范符合性判定 · 可解释多 Agent · 三维语义可视化 · 生存分析 · 预测性合规

---

## 摘要

现行 BIM 审查系统只解决"图模一致性"（模型与图纸一不一致），而"规范符合性"（构件是否满足消防、机电等强制性条文）仍靠人脑逐条对照，是数字化审查"最后一公里"的空白；城市生命线安全工程则进一步要求合规从"交付时快照"走向"全生命周期预测"。

本项目已建成 ArchCheck 原型：**确定性规则引擎负责判定、大模型负责读懂与叙述**，覆盖六专业 50 条审查规则，在 31 个真实/官方/机电 IFC 模型上通过六维基线与逐构件真值互检（建筑类几何正确率 99%+，7 个真实建筑模型达 S/A 级）。

下一步沿两个维度升级：**空间上**，以真实三维网格替代房间轮廓拉伸，实现违规构件三维锚定与疏散路径三维热力图；**时间上**，引入 Kaplan–Meier 与 Cox 生存回归，输出构件剩余寿命与失效风险，并将"预测性规则"接入合规引擎。二者在 **4D 风险演化**场景收口：三维 BIM 模型 × 时间轴 × 合规规则，回答"风险在哪里、何时发生、是否违规"。

## 一、灵感来源与立项依据

### 1. 政策背景：BIM 智能审查已从"试点"变为"制度"

- **顶层设计**：住建部 2024 年底启动"工程建设项目全生命周期数字化管理改革试点"，要求施工图审查等环节采用 BIM 成果提交与智能辅助审查；2025 年 3 月印发《智能建造技术导则（试行）》，确立"BIM+AI"贯穿全生命周期的路线。
- **地方落地**：河北、上海、海南、安徽等地已强制或全面上线 BIM 审查系统，如安徽省级平台围绕 5 大专业、139 个审查要点开展审查。

### 2. 核心痛点：制度先行，工具滞后，规范符合性审查仍是空白

- 现行 BIM 审查系统的能力边界仅限于**图模一致性**——模型画得对不对、与图纸一不一致。
- 长沙奥体中心试点的"AI 审图三件套"显示图纸核查效率提升 50%，但核心仍是图纸比对，**无法判定构件本身是否符合 GB 消防、机电等规范**。
- 规范条文频繁更新，软件硬编码规则随之滞后；条文判定仍依赖"人脑+条文"。这就是本项目切入的"最后一公里"。

### 3. 延伸痛点：城市生命线需要"预测性"

政策明确提出"房屋安全动态监测""城市生命线安全工程"。现有审查都是"当下快照"：楼今天合规，但 3 年后管道锈蚀、防火门下沉导致不合规怎么办？由此引入生存分析——合规不仅要判"现在"，还要回答"未来何时可能不合规"。

| 政策/行业需求 | 现状缺口 | 本项目对应能力 |
|---|---|---|
| 全生命周期数字化、智能建造 | 工具停在图模比对 | 规范符合性自动判定引擎 |
| 规范频繁更新、规则滞后 | 硬编码维护成本高 | RAG 知识库 + 条文→规则半自动生成 |
| 审查问责制 | AI 黑箱判定不可追溯 | 确定性判定，AI 仅做语义归一化与叙述 |
| 城市生命线、动态监测 | 只有交付快照 | 生存回归 + 预测性规则 + 4D 风险演化 |

## 二、现阶段研发进度（ArchCheck 原型）

> 数据截至 2026-09-17，所有数字可由仓库脚本与测试集复算。

原型已跑通"**读取 → 语义归一化 → 确定性判定 → 真值互检 → 可视化与导出**"完整闭环。

### 1. 多 Agent 可解释架构："模型负责读懂，规则负责判"

```
IFC 上传
 → ① BIM Reader       IFC 解析 + 模型可用性 QA（健康度 0-100，致命问题阻断）
 → ⓔ AI 语义预处理层   把多语言/缺失/混乱语义归一为标准枚举（房型/材料/管道系统）
 → ② Compliance Judge 确定性规则引擎：六专业 50 条规则判定
 → ④ Reasoner         LLM 审查叙述、跨专业冲突协调
                       ③ KB Steward 提供规范 RAG 检索与动态阈值
 ⑤ Independent Reviewer 规范原文复核（概念保留）
```

**LLM 不参与判定**：判违规的权力 100% 在确定性规则引擎，结论可复算、可审计、可追溯到条文，满足审查问责要求；大模型只做"读懂描述"和"讲清结果"两件事。

### 2. 规则库与规范知识库

- **六专业 50 条规则**：消防疏散 13 / 机电 13 / 全楼综合 9 / 电气 6 / 无障碍 5 / 结构 4；支持多操作符、适用条件过滤、跨楼层聚合、跨专业冲突检测、公式化动态阈值。
- **RAG 知识库**：36 份规范文档（免费规范全文入库，付费标准仅建索引，版权合规），实现"规范条文 → LLM 生成 JSON 规则 → 校验 → 人工确认"的半自动规则产线，直接回应规则滞后痛点。

### 3. AI 隐形语义预处理层（9 月最新成果）

真实模型语义常是"脏"的：德语房间名、纯编号 `101`、空白材料栏（信息只藏在 `Holzstuetze`=木柱这类构件名里）、无系统名管道。关键词覆盖不到时，木柱被当混凝土柱套规则 → 误报。

AI 位于判定**之前**且**完全隐形**，五条约束保证安全：①只填 Unknown，高置信结果不重判；②几何数字零写入，只能写三个语义枚举；③受控词表 + 枚举校验，越界即弃；④每条结论记账（原值/新值/来源/理由）；⑤整栋一次批量调用 + 哈希缓存 + 断网降级。

34 题人工金标（含一批"正确答案就是未知"的反幻觉题）：

| 类别 | 总准确率 | 覆盖率 | 已归类精确率 | 无依据乱猜 |
|---|:---:|:---:|:---:|:---:|
| 房型 | 81.0% → **90.5%** | 33.3% → 42.9% | 100% | **0** |
| 材料 | 61.5% → **100%** | 30.8% → 69.2% | 100% | **0** |

过程中真实抓到并修复了幻觉风险（AI 曾凭房间面积猜用途、把泛型楼板默认成混凝土）。收紧后编号房间全部诚实弃权，有文本证据的才分类。

### 4. 数据诚实机制

- 缺规则所需字段时**不假通过**，转报"未检查（缺字段 X）"，补字段即自动激活；
- 无证据的房型标 Unknown；参数标注来源（🟢模型 / 🟠默认待填）；
- 上传先做 QA 体检，致命问题（如纯机电模型无房间）宁可降档也不硬审。

### 5. 读取能力

- 建筑：房间几何面积、门宽三级回退、墙梁柱板、楼梯栏杆、英制单位、斜构件；
- 机电：管件配件、数量集、系统分类；**管道网络拓扑**（端口连接/系统归属，管型识别率 29%→86%）、消火栓间距推算；
- 性能：冲突检测包围盒缓存，Lab.ifc 解析 49s → 4.4s。

### 6. 可信度验证：逐构件互检 + 31 模型基线

- **逐构件真值互检（v6）**：以 IFC 文件真值为基准，按 GlobalId 逐件对齐提取值，结果按真实坐标标到平面图（绿对/红错/橙漏/紫多）。FZK-Haus 103 件全部正确；Archicad9 老导出的 Jasmin 几何正确率 77.5%→**100%**；**建筑类模型几何正确率 99%+**，唯一残留红色为建模口径问题（楼梯休息平台建成楼板）。
- **31 个 IFC 六维基线**（官方基准 / 9 个真实工程项目 / 5 类机电专项；六维：健壮性、提取完备、字段填充、几何准确、规则激活、性能）：
  - **7 个真实建筑模型达 S/A 级**；
  - FZK-Haus 91.0 分 S：墙 13/门 5/窗 11/梁 51/板 4 全读，审出 26 条真实问题；
  - Revit-MEP 84.3 分 A：2251 个机电实体全读，1034 条问题按 High/Low/Missing 分层；
  - 官方样例三版本读数一致，并稳定暴露固定提取缺口，作为回归标尺。
- 结论：**读取能力已近解析天花板，下一瓶颈是数据从哪来、几何与风险如何被直观看见**——即第三部分两条路线的依据。

### 7. 可视化与导出

- 结果页 V2.1：判定列表与视图双栏、专业筛选、3D 等轴视图（当前为房间轮廓拉伸）；
- **二维交互查看器（收尾中）**：悬停即出 tooltip，点击看尺寸/GlobalId/材料/触发规则条文，问题列表与图上构件双向高亮；
- **三维开源引擎选型已启动**（That Open Engine/web-ifc 本地已搭，xeokit、Speckle、three.js 等为候选）；
- 导出 HTML / Excel / BCF 2.1 / COBie；BCF 视点（相机位姿 + 构件 GUID）为三维违规锚定打底。

### 8. 现存不足（即攻关点）

1. 三维尚非真实网格；
2. 非拉伸体管件长度口径未统一（机电管长互检 64.5%）；

3. 住宅房型词表待补；
4. 耐火等级、照度等稀有属性公开模型普遍缺失；
4. 判定只有"交付快照"、无时间维度。

## 三、下一步技术演进：3D 视觉与生存分析的统一场景

核心思路：**3D 视觉回答风险"在哪里"，生存分析回答"何时发生"，合规引擎是连接两者的规则层。**

### 计划一：空间维度升级（3D 语义视觉）

1. **真实网格渲染**：不自研 CSG 内核。经开源选型实测后，在"IfcOpenShell 离线输出 GLB、按楼层切分缓存"与"集成 Web 端 IFC 引擎"之间定稿；验收：FZK 百件流畅、Revit-MEP 两千余件可拾取。
2. **违规构件三维锚定**：复用 BCF 2.1 视点（相机位姿 + GUID 列表），点违规项即在三维高亮构件并弹出条文；二维联动已验证，三维复刻。
3. **疏散路径 3D 热力图**：将已有房间邻接图 + Dijkstra 最远点疏散距离三维化，按距离热力着色。
4. **三维 AI 交互（探索）**：自然语言定位构件、AI 通俗解释违规、框选区域问题汇总。红线不变：**AI 只解释、不判定**。

### 计划二：时间维度升级（生存回归分析）

1. **合成维保数据**：扩展自有 IFC 生成器，按 **Weibull 生存函数**为防火门、喷淋、管道等生成 10 年维保时序（年龄、材料、楼层环境、维修次数为协变量）。生成器可控即天然拥有 Ground Truth，可量化模型准确率——与互检验真的方法论一脉相承。
2. **生存建模**：**Kaplan–Meier** 估计生存曲线、**Cox 比例风险模型**估计风险比，输出构件剩余寿命与瞬时 hazard。
3. **预测性规则接入**：引擎新增第四类规则形态——**预测失效日期早于下次法定检修周期 → 预防性预警**；维保数据不足则报"未检查（缺维保数据）"，绝不编造寿命。
4. 退化模型参数（门下垂、钢管锈蚀、喷头堵塞）按构件族配置，证据等级（规范/文献/合成假设）在规则中标注。

### 计划三：4D 风险演化（统一收口）

三维真实网格 + 时间轴滑块（2026 → 2036）：构件颜色随 hazard 由绿变红；点击构件同时看到"当前符合性 + 预期失效年份 + 建议检修窗口 + 规范依据"。**空间 × 时间 × 领域规则**的统一场景，直接对接城市生命线"动态监测、预测预警"。

### 排期建议

| 阶段 | 空间线 | 时间线 |
|---|---|---|
| 1 | 二维收尾；三维选型报告 + 真实 IFC 最小加载实测 | 维保生成器设计（构件族/协变量/Weibull 参数） |
| 2 | 三维原型（加载/拾取/着色/违规锚定） | 合成 10 年时序 + Ground Truth 校验 |
| 3 | 疏散 3D 热力图 | KM/Cox 建模 + 预测性规则入引擎 |
| 4 | 4D 时间轴集成、统一场景演示与论文撰写 | |

## 四、价值总结

1. **学术价值**：BIM、大语言模型（RAG 规则生成、语义归一化）与可靠性工程（生存分析）交叉，面向"可解释 AI 审查"有明确论文产出空间（*Automation in Construction* 等方向）；受约束 LLM 架构、反幻觉金标、真值互检方法学本身亦具方法论贡献。
2. **行业价值**：响应全生命周期数字化管理与智能建造政策，补齐现行 BIM 审图缺失的**规范符合性判定**与**预测性预警**两块短板；4D 场景对接城市生命线与房屋安全动态监测。
3. **可信治理价值**：坚持"模型负责读懂、规则负责判、几何数字绝不改、没证据就弃权"，AI 增益可追溯、可复算、零回归——为高问责的工程审查场景提供"敢用的 AI"范式。
