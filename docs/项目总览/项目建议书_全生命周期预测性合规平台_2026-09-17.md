# 项目建议书

# ArchCheck：从 BIM 智能审图到建筑全生命周期预测性合规平台

> 版本：V1.0 ｜ 日期：2026-09-17
> 关键词：BIM+AI 智能审查 · 规范符合性判定 · 可解释多 Agent · 三维语义可视化 · 生存分析 · 预测性合规
> 原型现状：ArchCheck V3.0（六专业 50 条规则/标准 · 31 模型基线 · 逐构件互检验真 · AI 语义预处理层）

---

## 摘要

现行 BIM 审查系统解决了"图模一致性"（模型画得对不对），但"规范符合性"（构件本身是否满足消防、机电等强制性条文）仍依赖人脑逐条对照，是建设工程数字化审查"最后一公里"的空白；而城市生命线安全工程进一步要求合规从"交付当下的快照"走向"全生命周期的预测"。

本项目已建成 ArchCheck 原型：以**确定性规则引擎负责判定、大模型负责读懂与叙述**的可解释多 Agent 架构，覆盖六专业 50 条审查规则、中国 GB 与新加坡 Fire Code 2023 双标准，在 31 个真实/官方/机电 IFC 模型上通过六维基线测评与逐构件真值互检（建筑类几何正确率 99%+，7 个真实建筑模型达 S/A 级）。

下一步沿两个维度升级：**空间维度**——以真实三维网格渲染替代房间轮廓拉伸，实现违规构件三维锚定与疏散路径三维热力图；**时间维度**——引入 Kaplan–Meier 与 Cox 生存回归，输出构件剩余寿命与失效风险，将"预测性规则"接入合规引擎。二者在 **4D 风险演化**场景中收口：三维 BIM 模型 × 时间轴 × 合规规则，形成"风险在哪里 × 何时发生 × 是否违规"的统一闭环。

## 一、灵感来源与立项依据（文献与数据支撑）

项目的立意升华，源于近期国内建筑行业在数字化与智能化转型上的一系列真实政策与数据。我们过去的定位是"AI 审图工具"，但在查阅行业现状后发现，项目完全可以切入国家政策落地的"最后一公里"痛点中。

### 1. 政策背景：BIM 智能审查已从"试点"变为"制度"

- **顶层设计**：住建部 2024 年底启动"工程建设项目全生命周期数字化管理改革试点"，明确要求在施工图审查等环节采用 BIM 成果提交与智能辅助审查；2025 年 3 月印发《智能建造技术导则（试行）》，确立"BIM+AI"贯穿工程全生命周期的技术路线。
- **地方落地**：河北、上海、海南、安徽等地已强制或全面上线 BIM 审查系统。例如安徽省建设了省级 BIM 审查平台，围绕 5 大专业、139 个审查要点开展审查。

> 待办：正式报送版需为上述政策名称、文号、时间与数据补充官方出处（住建部通知原文、地方平台公开报道），逐条可核。

### 2. 核心痛点：制度先行，工具滞后，规范符合性审查仍是空白

- 现行 BIM 审查系统的能力边界仅限于**"图模一致性"**（模型画得对不对、与图纸一不一致）。
- 长沙奥体中心项目试点的"AI 审图三件套"数据显示，图纸核查效率可提升 50%，但其核心仍是"图纸比对"，**无法完成"规范符合性"审查**——即建筑构件本身是否符合 GB 消防、机电等强制性规范。
- 传统的规范条文判定仍依赖"人脑 + 条文"；规范条文频繁更新，而软件规则一旦写死便滞后于规范。这正是本项目要切入的"最后一公里"。

### 3. 延伸痛点：城市生命线安全工程对"预测性"的需求

- 住建部《新型城市基础设施建设行动方案》及多地政策明确提出"房屋安全动态监测""城市生命线安全工程"。
- 现有合规审查都是"当下快照"——这栋楼今天合规，但 3 年后管道锈蚀、防火门下沉导致不合规怎么办？这直接引出本项目拟引入的**生存分析**方向：合规不仅要判"现在合不合规"，还要回答"未来何时可能不合规"。

### 4. 立项依据小结

| 政策/行业需求 | 现状缺口 | 本项目对应能力 |
|---|---|---|
| 全生命周期数字化管理、智能建造导则 | 审查工具停留在图模比对 | 规范符合性的自动判定引擎（第二部分） |
| 规范频繁更新、硬编码规则滞后 | 规则维护成本高、滞后 | RAG 知识库 + 条文→规则半自动生成 |
| 审查机构问责制 | AI 黑箱判定不可追溯 | 确定性判定 + AI 仅做语义归一化与叙述，100% 可审计 |
| 城市生命线、房屋安全动态监测 | 只有交付时快照，无预测 | 生存回归 + 预测性规则 + 4D 风险演化（第三部分） |
| 中国标准"一带一路"出海 | 工具仅支持单一本土规范 | CN GB / SG Fire Code 双标准架构，可配置扩展 |

## 二、现阶段研发进度（ArchCheck V3.0 原型）

> 数据截至 2026-09-17。本部分所有数字均可由仓库内脚本与测试集复算。

我们并非从零开始。ArchCheck 原型已完成"**读取 → 语义归一化 → 确定性判定 → 真值互检 → 可视化与导出**"的完整闭环，为后续三维渲染与生存分析提供坚实底座。

### 1. 多 Agent 可解释架构："模型负责读懂，规则负责判"

系统按职责划分为五个角色 Agent，并在 2026 年 9 月新增一个**隐形的 AI 语义预处理层**：

```
IFC 上传
 → ① BIM Reader        IFC 解析 + 模型可用性 QA 体检（健康度 0-100，致命问题阻断）
 → ⓔ AI 语义预处理层    把多语言/缺失/混乱的语义"读懂"为标准枚举（房型/材料/管道系统）
 → ② Compliance Judge  确定性规则引擎：六专业 50 条规则判定
 → ④ Reasoner          LLM 审查叙述、跨专业冲突协调
                        ③ KB Steward 提供规范 RAG 检索与动态阈值
 ⑤ Independent Reviewer 规范原文复核（概念保留）
```

核心哲学始终未变：**LLM 不参与合规判定本身**。判违规的权力 100% 留在确定性规则引擎，结论可复算、可审计、可追溯到规范条文，满足审查机构的问责制要求；大模型只做两类它真正擅长的事——把混乱描述读懂、把判定结果讲清楚。

### 2. 双标准规则库与规范知识库

- **规则库**：覆盖消防疏散、机电、电气、结构、全楼综合、无障碍六专业，**每地区 50 条**（消防 13 / 机电 13 / 全楼 9 / 电气 6 / 无障碍 5 / 结构 4），中国 GB ↔ 新加坡 Fire Code 2023 一键切换、双语 UI；新地区标准只需放入一个规则包文件夹即可扩展。
- 规则引擎能力：多操作符、适用条件过滤、规则专业 scope 分发、跨楼层聚合、跨专业冲突检测、公式化动态阈值（如梁高随跨度变化），以及"缺字段诚实上报"机制。
- **RAG 知识库**：36 份规范文档物料（免费规范全文入库，付费标准仅建索引、不收全文，版权合规），并实现"规范条文 → LLM 生成 JSON 规则 → 校验 → 人工确认"的半自动规则产线，直接回应"规范更新导致规则滞后"的痛点。

### 3. AI 隐形语义预处理层（2026 年 9 月新增，原型最新成果）

真实 BIM 模型的语义往往是"脏"的：房间名是德语 `Besprechungszimmer` 甚至纯编号 `101`，材料栏写着 `Beton C25/30` 或留空（信息只藏在构件名 `Holzstuetze`=木柱里），管道没有系统名。关键词匹配覆盖不到，木柱被当混凝土柱套规则 → 误报。

方案把 AI 放在判定**之前**且**完全隐形**，并施加五条工程约束：

1. **只填空**：关键词已高置信判定的对象绝不重判，只送 Unknown/低置信项；
2. **几何数字零写入**：AI 只能写房型、材料类、管道系统三个语义字段，尺寸/面积/距离/计数对其只读；
3. **受控词表 + 枚举校验**：只能从给定选项中选择，越界返回直接丢弃；
4. **集中记账、可追溯**：每条 AI 结论记录原值、新值、来源、置信度与理由；
5. **整栋一次批量调用 + 哈希缓存 + 优雅降级**：无 API/断网时行为与纯关键词流程完全一致。

34 题人工金标（故意包含"正确答案就是未知"的反幻觉考题）实测：

| 类别 | 总准确率 | 可归类覆盖率 | 已归类精确率 | 无依据乱猜 |
|---|:---:|:---:|:---:|:---:|
| 房型 | 81.0% → **90.5%** | 33.3% → 42.9% | 100% | **0** |
| 构件材料 | 61.5% → **100%** | 30.8% → 69.2% | 100% | **0** |

研发中还真实抓到并修复了一次幻觉风险：模型曾"仅凭房间面积猜用途、把泛型楼板默认成混凝土"。收紧为严格证据策略后（候选只发名字不发尺寸、纯编号必须弃权、词表外功能必须弃权），编号房间全部诚实弃权，有真实文本证据的才给分类。三个真实模型增强前后违规总数变化为 **0**、几何零改动。

### 4. 数据诚实机制（工程审查的生命线）

- 模型缺规则所需字段时，**不假通过**，规则转报"未检查（缺字段 X）"，模型补字段即自动激活判定；全字段为空的规则折叠显示，不刷屏。
- 房间类型无证据时标 Unknown；参数区分来源（🟢 来自模型 / 🟠 默认值待填写）。
- 模型上传先做 QA 体检并打健康分（长度单位、空间完整性、几何有效性、空间边界引用、实体覆盖度），致命问题阻断审查——例如纯机电模型无房间时，平台宁可降档也不硬审。

### 5. 工程化读取能力（互检驱动，逐件修复）

- 建筑类：楼层/房间几何面积、门宽三级回退（属性→名称→包围盒）、墙梁柱板、楼梯、栏杆、英制单位推断、斜构件与 MappedItem 几何处理。
- 机电类：管件配件、数量集、材料、系统分类、Qto-Profile 单位抽样推断；**管道网络拓扑**（端口连接/系统归属/系统名回填管型，管道用途识别率 29% → 86%）；消火栓间距推算。
- 性能：冲突检测缓存各元素包围盒，Lab.ifc 解析由 49s 降至 4.4s。

### 6. 可信度验证：逐构件互检 + 31 模型六维基线

这是原型区别于"演示型 Demo"的关键——我们用两套独立机制验证系统读得对不对：

- **逐构件真值互检（crosscheck v6）**：以 IFC 文件内真值为基准，按 GlobalId 逐件对齐"平台提取值"，比对分类、几何尺寸与计数，结果按真实坐标标到楼层平面图（绿对/红错/橙漏/紫多）。结果：FZK-Haus 103 个构件全部正确（仅 2 个纯编号房间的类型分类存异）；Archicad9 老导出的 Jasmin 住宅几何正确率从 77.5% 修复到 **100%**；**建筑类模型几何正确率 99%+**，唯一残留红色为"楼梯休息平台被建模成楼板"的建模口径问题。
- **31 个 IFC 模型六维基线测评**：测试集含 buildingSMART 官方基准（IFC2x3/4/4.3）、9 个真实工程项目（FZK、Jasmin、HITOS、Smiley、4351、Basic 等）与 5 类机电专项模型，按健壮性/提取完备/字段填充/几何准确/规则激活/性能六维打分：
  - **7 个真实建筑模型达 S/A 级**；
  - FZK-Haus：91.0 分 S 级，墙 13/门 5/窗 11/梁 51/板 4 全部读全，审出 26 条真实问题；
  - Revit-MEP（28MB）：84.3 分 A 级，2251 个机电实体全部读全，审出 1034 条问题并按 High/Low/Missing 分层；
  - 官方迷你样例三版本读数一致，同时稳定暴露"3 块楼板只读 1 块"这类固定提取缺口，作为回归标尺。
- 测评结论：**读取能力已接近解析天花板，下一阶段瓶颈在"审查要的数据从哪来"以及"几何与风险如何被直观看见"**——这正是第三部分两条升级路线的依据。

### 7. 可视化与交付物

- 结果页 V2.1：按 Agent 组织、判定列表与视图双栏、专业筛选、双标准切换对比；
- **二维交互查看器（已完成原型，收尾中）**：高清楼层平面底图，悬停即出 tooltip（构件名/IFC 类型/楼层/关键尺寸/互检状态），点击弹出详情面板（三轴尺寸、GlobalId、材料及 AI 归一化标注、触发规则 ID 与规范条文），问题列表与图上构件双向高亮联动；
- 三维方向：现结果页为房间轮廓拉伸堆叠的等轴视图；**开源三维引擎选型调研已启动**（That Open Engine/web-ifc 已在本地搭建，xeokit-sdk、Speckle、three.js、FreeCAD/Bonsai 为对比候选）；
- 报告导出：HTML / Excel / BCF 2.1 / COBie；BCF 视点（相机位姿 + 构件 GUID 列表）为后续三维违规锚定奠定基础。

### 8. 现存不足（如实陈述，亦是立项后的攻关点）

1. 三维尚非真实网格，大模型构件级拾取、剖切与标注能力待建；
2. 非拉伸体管件的几何长度口径未统一（机电管长互检正确率 64.5%）；
3. 房型受控词表偏公共建筑，住宅房型及对应规则待补；
4. 稀有工程属性（耐火等级、照度、疏散指示灯具）在公开模型中普遍缺失；
5. 合规判定只有"交付时快照"，无时间维度——直接对应计划二。

## 三、下一步技术演进计划：3D 视觉与生存分析的统一场景

结合导师建议，项目从"静态合规审查"升级为"全生命周期预测性合规"。核心思路：**3D 视觉解决风险在空间上"在哪里"，生存分析解决风险在时间上"何时发生"，合规引擎是连接两者的规则层。**

### 计划一：空间维度升级（3D 语义视觉）

目前结果页的三维视图仅为房间轮廓拉伸堆叠，下一步进行深度重构（技术路线先完成开源选型评测，再定自研集成度）：

1. **真实网格渲染**：坚持 B-Rep 调研结论——不自研 CSG 内核。候选路线：以 IfcOpenShell 几何管线离线输出 GLB 三角网格、按楼层切分缓存（顺带解决大模型解析慢的问题）；或直接集成 Web 端开源 IFC 引擎（That Open Engine / xeokit-sdk），在 2–3 个真实 IFC（含 Archicad 老导出、Revit 2000+ 管件量级）上完成最小加载实测后定稿。验收：FZK 百件流畅、Revit-MEP 两千余件可拾取。
2. **违规构件三维锚定**：复用已有 BCF 2.1 导出逻辑（viewpoint 本质是相机位姿 + 构件 GUID 列表）。判定列表与三维模型联动，点击违规项即在三维中高亮构件并弹出规范条文；该能力在二维交互查看器上已先行验证（hover/详情/双向联动），三维复刻即可。
3. **疏散路径 3D 热力图**：将已有的房间邻接图 + Dijkstra 最远点疏散距离算法三维化，按疏散距离对房间/路径热力着色，强化消防专业的直观说服力。
4. **三维场景中的 AI 交互（探索项）**：自然语言定位（"找出所有宽度不足的疏散门"）、AI 通俗解释违规成因、框选区域问题汇总。红线不变：**AI 只解释、不判定，结论可回溯到规则与条文。**

### 计划二：时间维度升级（生存回归分析）

这不仅是论文素材，更是项目立意的升华——从合规审查走向全生命周期预警：

1. **合成维保数据生成**：真实维保数据难获取，拟扩展自有 IFC 生成器，按 **Weibull 生存函数**为防火门、喷淋头、管道等构件生成 10 年维保时序（含年龄、材料、楼层环境、维修次数等协变量）。因生成器完全可控，天然拥有 Ground Truth，可量化后续模型的准确率，避免"无真值的自说自话"——与本项目互检验真的方法论一脉相承。
2. **生存回归建模**：使用 **Kaplan–Meier** 估计生存曲线、**Cox 比例风险模型**估计各协变量风险比，输出每个构件的剩余寿命与瞬时失效 hazard。
3. **预测性规则接入**：扩展 Compliance Judge，在现有"即时违规""缺字段未检查"之外新增第四类规则形态——**预测失效日期早于下次法定检修周期 → 预防性预警**。同样套用诚实上报机制：维保数据不足的构件报"未检查（缺维保数据）"，绝不编造寿命。
4. **可配置退化模型**：不同构件族（防火门下垂、钢管锈蚀、喷头堵塞）采用不同 Weibull 参数与协变量集，参数来源（规范/文献/合成假设）在规则中标注，区分证据等级。

### 计划三：统一场景的视觉收口（4D 风险演化）

将两条线统一：在三维真实网格模型上增加时间轴滑块——

- 拖动时间轴（2026 → 2036），构件颜色随生存模型输出的 hazard 概率由绿变红；点击任一构件，同时看到"当前规范符合性 + 预期失效年份 + 建议检修窗口 + 规范依据"；
- 这就是最终的"统一场景"：**空间（3D BIM 语义模型）× 时间（生存回归分析）× 领域（合规规则引擎）**，也是向城市生命线"动态监测、预测预警"要求交付的直观形态。

## 四、价值总结

通过上述演进，项目不只是"一个能看三维模型的工具"，而是形成具有学术深度与应用价值的闭环：

1. **学术/科研价值**：将建筑信息模型（BIM）、大语言模型（RAG 规则生成与语义归一化）与可靠性工程（生存分析）交叉，在"可解释 AI 审查"方向有明确的论文产出空间（*Automation in Construction* 等期刊方向）。"确定性判定 + 受约束 LLM"的架构、34 题反幻觉金标、逐构件真值互检方法学，本身也具备方法论贡献。
2. **行业应用价值**：响应住建部"工程建设项目全生命周期数字化管理"与"智能建造"政策，补齐现行 BIM 审图系统缺失的**"规范符合性判定"**与**"预测性预警"**两大短板；4D 风险演化场景可直接对接城市生命线安全工程与房屋安全动态监测。
3. **标准化与出海价值**：CN GB / SG Fire Code 双标准、规则包配置化扩展的架构，可服务于中国工程建设标准"一带一路"出海。
4. **治理与可信价值**：坚持"模型负责读懂、规则负责判、几何数字绝不改、没证据就弃权"，AI 增益全部可追溯、可复算、零回归——为工程审查这类高问责场景提供一份"敢用的 AI"范式。
