## 二、项目摘要（≤300 字）

高校大量历史建筑在承担教学功能的同时，正面临墙体老化、裂缝扩展、渗水剥落等"沉默的病害"；传统人工巡检效率低、主观性强，且无历史数据可比对。2024 年河南大学大礼堂火灾等事故已敲响警钟，多所高校的文物级建筑正面临"不可逆损毁"风险。

本项目依托团队已有的 BIM 解析与三维可视化原型（ArchCheck），构建面向校园历史建筑的数字化健康监测平台：用手机/无人机照片 + 深度学习识别墙体裂缝、剥落、水渍等典型病害；用 HBIM（历史建筑信息模型）建立每栋楼的"数字档案"；用生存分析预测病害发展趋势与下次检修窗口。项目以本校 1–2 栋老建筑为试点，产出可向全校推广的"一楼一档"健康档案模板，兼具技术训练价值与校园文化保护意义。

## 三、立项依据

### 3.1 校园历史建筑保护是真实且紧迫的需求

**（1）校园历史建筑的老化风险真实且紧迫**

- **2024 年 5 月 2 日晚，河南大学明伦校区大礼堂在修缮施工期间发生火灾**，造成部分屋顶坍塌、建筑烧损；该建筑是第六批全国重点文物保护单位"河南留学欧美预备学校旧址"的重要组成部分（1931 年动工、1934 年建成），事故由国务院安委会挂牌督办。校园内的文物建筑一旦损毁，难以复原。
- 高校老建筑多为砖木结构、建造年代久远，普遍存在**墙体老化、裂缝扩展、渗水剥落、木构件糟朽**等问题；又长期承担教学与办公功能，损耗速度往往快于一般文物建筑。
- 传统巡检依赖后勤人员定期"走看 + 拍照"，**主观性强、漏检率高、无法量化比对**，"这面墙到底恶化到什么程度、什么时候必须修"缺少判断依据。

**（2）AI 与数字化手段已被证明可行，但预测性应用仍是空白**

- **东南大学土木工程学院高康教授团队的"AI 体检"体系**：以无人机广域初筛 + 爬壁机器人定点精检采集影像，AI 自动识别**混凝土裂缝、瓷砖脱落、金属锈蚀、墙体水渍等 50 类外立面典型损伤**，单栋建筑全维度评估由人工约一周压缩至**半小时**，团队自建超百万张建筑病害图像数据集。这说明"影像采集 + 深度学习识别"的路径已能支撑建筑病害的规模化筛查。
- **HBIM（历史建筑信息模型）** 已是遗产保护领域的成熟研究方向：将三维扫描、摄影测量与历史、材料、病害信息整合为数字孪生，作为病害诊断与修缮决策的基础。
- 但现有工作多面向公共建筑或文物单位，**面向高校校园、并把"病害识别"继续推进到"未来何时需要修缮"的预测性应用仍属空白**——这正是本项目的切入点。

### 3.2 校内现实痛点（本项目切入的具体问题）

| 痛点 | 校园真实场景 |
|---|---|
| 巡检靠人眼 | 后勤/基建处对老建筑的巡检以定期走查看照片为主，主观性强、漏检率高 |
| 无历史数据 | 每次巡检是"独立快照"，无法比对"去年这条裂缝长了多少""这块墙面今年风化到什么程度" |
| 无数字档案 | 多数老建筑只有纸质图纸，没有三维模型，修缮时需要重新测绘 |
| 无预警机制 | 病害从"看起来还行"到"需要大修"之间缺乏量化指标，往往被动等出问题 |

### 3.3 项目可行性

- **技术基础已具备**：团队已完成 ArchCheck 原型，**IFC 解析、模型可用性体检（QA）、二维/三维可视化、BCF 2.1 导出**链路全部跑通，并在 **31 个真实/官方 IFC 模型**上完成六维基线测评与逐构件真值互检——**7 个真实建筑模型达 S/A 级，建筑类几何提取正确率 99%+**。本项目所需的"模型解析 + 三维展示 + 构件级锚定"能力可直接复用，不必从零开发。
- **场景贴近**：本校老建筑数量适中（初步调研 [X] 栋），无需复杂设备，手机相机 + 开源深度学习模型即可完成病害图像采集与识别。
- **成本可控**：校级经费即可支撑（采集设备、GPU 算力、文献资料）；核心算法均基于开源框架（PyTorch、IfcOpenShell、scikit-survival），无授权费用。

## 四、研究内容与技术路线

### 4.1 三条研究内容

**内容一：校园历史建筑 HBIM 数字档案构建**

- 用手机摄影测量（或租赁三维扫描服务）采集目标建筑点云/照片，通过 IfcOpenShell 构建 BIM 模型；
- 挂接历史信息（建造年代、历次修缮记录、结构类型、材料），形成"一楼一档"；
- 复用 ArchCheck 已有的 IFC 解析、模型 QA、BCF 导出能力，不重复造轮子。

**内容二：基于深度学习的病害图像识别**

- 采集墙面照片（手机即可），用 U-Net 或 YOLO 系列开源模型做裂缝/剥落/水渍/风化的图像分割与识别；
- 参考东南大学"AI+体检"的病害分类体系（50 类），结合校园老建筑特点精简为 **10–15 类高频病害**；
- 建立小型校园病害图像数据集（目标 **500–1000 张**标注样本），形成可复用的校本研究资产。

**内容三：基于生存分析的病害发展趋势预测**

- 每次巡检结果（病害位置、类型、严重度）按时间戳写入 HBIM 档案，形成时序数据；
- 用 **Kaplan-Meier** 估计"病害从出现到需要修缮"的生存曲线，用 **Cox 比例风险模型**分析影响因素（朝向、材料、使用强度、是否临水临路）；
- 输出每处病害的"预计需要检修的时间窗口"，配合巡检周期生成修缮建议——这是团队原规划中"预测性预警"思路在校园场景的直接落地。

### 4.2 统一场景：3D 健康档案可视化

在 HBIM 三维模型上叠加病害图层：

- 每处病害按 GlobalId 锚定到三维构件位置，点击查看照片 + 历史记录 + 预测信息；
- 用时间轴滑块查看某栋楼过去 N 年的病害演化；
- 输出 HTML 报告（含 3D 视图 + 病害照片 + 修缮建议），直接提交后勤处参考。

### 4.3 技术路线图

```
校园老建筑
    │
    ├── 手机摄影测量 / 无人机照片 ──→ HBIM 三维档案（复用 ArchCheck BIM Reader）
    │
    ├── 墙面照片 ──→ 深度学习病害识别（U-Net / YOLO）
    │                  ↓
    │             病害清单（位置 / 类型 / 严重度）
    │                  ↓
    └── 定期巡检 ──→ 时序病害数据 ──→ 生存分析（KM / Cox）
                                       ↓
                                 预测检修窗口
                                       ↓
                       3D 健康档案 + HTML 修缮报告
                       （提交后勤 / 基建处参考）
```

## 五、创新点

1. **方法创新**：将 HBIM（历史建筑数字孪生）与生存分析结合，从"病害记录"升级为"病害预测"，突破传统巡检"只看当下"的局限——这一组合在校园场景尚无成熟应用。
2. **数据创新**：建立校园老建筑病害图像数据集与"一楼一档"健康档案模板，可向其他高校推广。
3. **场景创新**：以本校老建筑为试点，学生直接走进现场采集数据、面对真实问题，避免"假数据、真论文"的空转。

## 附录一：给评审老师的两句话说明

如果评审老师问"这个项目跟一般的 AI 识图有什么不一样"，可以这样回答：

> 一般 AI 识图只回答"现在有没有裂缝"；我们的平台在此基础上回答三件事：**这条裂缝在建筑三维模型上的哪个位置**（HBIM 构件级锚定）、**它跟去年的照片比是变大了还是稳定了**（时序对比）、**按照它的材料和使用环境预计多久需要修缮**（生存分析预测）——把"拍照识别"升级为"建筑的全生命周期健康管理"。这既是项目的技术独特性，也是它能服务校园实际管理的价值所在。
