# ArchCheck「真实可用」目标路线图（对标行业标准）

> 归属：`presentation/2026-08-20/` · 制定日期 2026-08-22
> 目标：读入 IFC → 全方位细节验证模型可行性 → 输出**可供实际施工使用的可信结果**
> 原则：先不纠结"做不做得到"，用行业标准定义"做到什么效果"；现状诚实标注。

---

## 0. 目标定义

一条链路：**IFC 读入 → 完整数据提取 → 全几何/语义/协调验证 → 规范合规判定 → 可信报告 → 实际施工可用**。

"真实可用"的三条验收底线：
1. **结果可信**：每个判定可追溯到数据与规范，付费标准不编条款号
2. **格式互操作**：问题/报告能用行业协作格式（BCF 等）流出，别的软件能直接接着用
3. **经得起真实项目**：在真实 IFC 上规模化跑，错误率可量化、可辩护

## 1. 对标哪些行业标准（为什么是它们）

| 标准/工具 | 作用 | 为什么对标它 |
|---|---|---|
| **IFC4x3 / buildingSMART MVD** | IFC 数据 schema 与模型视图定义 | 定义"读 IFC 到什么才算完整" |
| **buildingSMART IDS**（Information Delivery Specification）| 机器可读的"每个构件必须带什么信息" | 定义"全方位验证"的最小要求 |
| **ISO 19650 / LOIN** | BIM 信息管理、Level of Information Need | 定义"多细才算可用" |
| **Solibri Model Checker / Navisworks** | 规则化检查 + 几何干涉检测 | 行业最接近"真实可用"的产品标杆 |
| **新加坡 CORENET / IBC** | 政府级自动规范审查（我们的最贴近先例）| 证明"自动规范审查"是真实需求 |
| **BCF（BIM Collaboration Format）** | buildingSMART 问题交换格式 | 定义"结果怎么流出给别的软件" |

## 2. 六个能力台阶（每级 = 行业对标 + 现状 + 关键动作）

### 台阶 1 · IFC 读取完备性 —— 对标 IFC4x3 schema
- **现状**：读 空间/门/结构/机电 基础；几何是 bbox/凸包近似；**不读**材料/数量/连接/系统连通
- **目标**：全 schema 关键实体 —— 实体几何（含拉伸体）、材料（IfcMaterial/LayerSet）、数量（IfcElementQuantity）、构件连接（IfcRelConnects）、分布系统（IfcDistributionSystem）
- **关键动作**：换/修 ifcopenshell 几何（当前无法处理 IfcExtrudedAreaSolid）；材料/数量/连接/系统读取器

### 台阶 2 · 模型质量验证 —— 对标 IDS + ISO 19650 LOIN
- **现状**：QA 只 4 项（单位/空间/几何/边界），查不出语义错误
- **目标**：**IDS 驱动质检** —— 用 IDS 表达"消防门必须带宽度、管道必须带系统"，自动核对缺失；IFC schema 合规 + 语义校验（房间类型/构件分类）；LOIN 符合性
- **关键动作**：实现 IDS 子集解析器 + 语义校验规则；扩展 QA 到"信息完整性"

### 台阶 3 · 精确几何与工程量 —— 对标 Solibri/Navisworks 几何引擎
- **现状（2026-08-22 推进）**：
  - ✅ ifcopenshell 0.8.5 **能处理 IfcExtrudedAreaSolid**（旧判断"处理不了"已推翻）
  - ✅ **精确面积**：三角投影求和替代凸包（L 型 27 vs 凸包 36）；office_3f 面积全精确
  - ✅ **面积未知诚实化**：无几何→"面积未知"、有 IfcBoundingBox→XDim×YDim 兜底
  - ✅ **体积提取（基本版）**：有符号四面体公式 → 柱/梁/板 volume_m3 + 每层结构体积（office_3f：柱 0.576/梁 0.48·0.72/板 96.9 m³ 全精确）
  - ✅ **混合单位修复**：`_length_scale` 交叉校验几何量级（声明毫米但构件米级的模型，如 Schependomlaan，几何用米）；`elev_scale` 单独归一化楼层标高 → Schependomlaan 结构 178 构件全提取、体积 287.4 m³、标高 0/3/6m
  - ✅ **材料量汇总**：`_elem_material`（IfcMaterial/LayerSet/List）+ 结构构件 `material` + 每层 `material_volumes` → 结果页"结构工程量（按材料）"展开器（Schependomlaan：预制混凝土 76.0/现浇 18.9/钢材 m³；无材料的如实"材料未知"）
  - ✅ **工程量表细化**：`qty_by_type`（按构件类型计数+体积）+ 每层/整楼结构体积总量
  - ✅ **基础干涉检测（粗检）**：`_detect_clashes` —— MEP（管/风管）bbox vs 梁/板/墙 bbox 穿透检测（余量 0.05m，排除柱子减少噪音）；结果页"潜在冲突候选（粗检）"展开器；office_3f 检出设计冲突 ClashPipe→梁 深 0.1m（每层）
  - ⬜ **布尔运算（级联/洞口）**：需 CSG 实体内核，作为独立大项暂缓（诚实标注，非静默省略）
- **目标**：精确实体几何（拉伸体/扫掠/布尔差）→ **真实体积/面积/数量提取**（施工要工程量）
- **剩余**：布尔运算（级联/洞口）、跨构件干涉（台阶 4 前置）、材料量汇总（结合 IfcMaterial）

### 台阶 4 · 干涉与协调检测 —— 对标 Navisworks clash / ISO 19650 协调
- **现状**：无干涉检测
- **目标**：跨专业 **clash**（建筑 vs 结构 vs 机电）、净空/净高真几何验证、冲突矩阵与分级
- **关键动作**：基于精确几何的碰撞对枚举 + 分级（硬/软/净空）

### 台阶 5 · 规范合规审查完备化 —— 对标 CORENET / Solibri Code
- **现状**：5 专业、每专业几条规则（消防 4 / 电气 4 / 结构 3 / 机电 4 / 无障碍近乎 0）
- **目标**：规则从"几十条"到**覆盖全规范**（消防/疏散/结构/机电/无障碍数百条）；**条文→机器规则**（规范条文驱动规则生成）；上下文/例外处理；动态阈值全推广
- **关键动作**：规则平台化（规则 DSL + 编辑器）、按规范章节系统化建规则、用 RAG+LLM 辅助条文→规则

### 台阶 6 · 交付与工程可信 —— 对标 openBIM 交付 / BCF
- **现状**：HTML/Excel 报告、自研 PNG
- **目标**：问题**以 BCF 导出**（可直接进 Revit/Navisworks/Solibri）；COBie 交付；IFC 带问题注释导出；真实项目规模化验证 + 与商业工具对标（检出率/误报率量化）
- **关键动作**：BCF 导出器、COBie 生成、真实项目测试集 + 基准评测

## 3. 里程碑与验收（6 台阶排布）

| 台阶 | 验收标准（做到什么才算过） |
|---|---|
| 1 读取完备 | 对 IFC4x3 样例：实体几何/材料/数量/连接/系统 全部提取，无崩溃 |
| 2 质量验证 | 用 IDS 定义样例要求 → 自动报出"缺宽度/缺系统/类型错"等，命中率可量化 |
| 3 几何工程量 | 精确算体积/面积与手工复核误差 < 2%；拉伸体模型能处理 |
| 4 干涉协调 | 合成缺陷样例（故意放一根穿墙管）→ clash 检出率 100%、无漏报 |
| 5 合规完备 | 消防/疏散规则覆盖主要章节；误报率 < 10%（金标准量化）|
| 6 交付可信 | BCF 能导入 Navisworks/Solibri；真实项目 10+ 个跑通；与 Solibri 对标报告 |

## 4. 现状定位（诚实）

站在 **台阶 1（部分）~ 台阶 5（基础）**：
- ✅ 已具备：真实 IFC 读入、基础数据提取、5 专业基础规则、真实模型端到端、语义检索证据、BCF 之外的报告导出
- ❌ 未具备：精确几何（台阶 3）、干涉检测（台阶 4）、规则完备（台阶 5 全量）、BCF/COBie 交付（台阶 6）

**离"真实可用"还隔着：精确几何 → 干涉检测 → 规则完备 → 交付互操作** 这四个台阶的工程。

---

## 5. 第一个落点建议

从 **台阶 3（精确几何）** 砸起 —— 它是地基：解锁 工程量、干涉检测、净空验证，全部下游能力都依赖"能处理精确实体几何"。当前最硬的墙是"ifcopenshell 本机无法处理 IfcExtrudedAreaSolid"，优先换几何后端。

> 一句话：我们现在是"能读真模型、能跑真规则"的可靠地基；往"真实可用"走，下一步是把几何做真，然后是协调、规则完备、交付互操作。
