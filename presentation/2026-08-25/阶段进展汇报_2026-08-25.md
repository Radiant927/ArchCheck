**MEP 规则集**

**真实 IFC 样例接入（2 个）**：

| 样例 | 规模 | 复杂度 | 用途 |
|---|---|---|---|
| Duplex_MEP | 17.8MB · IFC2X3 · 纯机电 | 管/风/卫浴齐全 | 验证 MEP 提取与 IFC2X3 兼容 |
| Schependomlaan | 49.3MB · 完整住宅 | 934 墙 / 205 门 / 60 管 / 178 结构 | 逼出混合单位问题、规模化稳定性 |

> Schependomlaan 是第一个逼出"声明 mm 但几何实际用米"的混合单位模型——我们修了 `_length_scale` 交叉校验和 `elev_scale` 标高归一化，现在能正确读出全部 178 个结构构件、287.4 m³ 体积、3 层标高 0/3/6m。

### 方向 4：精确几何与工程量（台阶 ③ 突破）

这是地基级的改进——之前几何只有 bbox/凸包近似，现在能做精确计算：

**精确面积**：三角投影求和（替代凸包）
- L 形房间：凸包算 36 m² → 精确算 27 m²，不高估
- office_3f 全部房间面积精确

**精确体积**：有符号四面体公式（散度定理）
- 柱 / 梁 / 板 volume_m3 全精确
- office_3f：柱 0.576 / 梁 0.48·0.72 / 板 96.9 m³
- Schependomlaan：结构总体积 287.4 m³

**材料量汇总**：
- 读 IfcMaterial / IfcMaterialLayerSet / IfcMaterialList
- 按材料汇总体积 → 结果页"结构工程量（按材料）"展开器
- Schependomlaan：预制混凝土 76.0 / 现浇 18.9 / 钢材若干 m³
- 无材料的构件如实标注"材料未知"（不编造）

**工程量表**：按构件类型（柱/梁/板/墙）统计数量 + 体积 + 每层/整楼总量

**混合单位修复**：
- `_length_scale`：交叉校验声明单位 vs 实际几何量级（Schependomlaan 声明 mm 但几何是米 → 自动修正为 1.0）
- `elev_scale`：单独归一化楼层标高（mm→m）
- 无几何的空间 → "面积未知"（诚实标注，不编数）
- 只有 IfcBoundingBox 的 → XDim×YDim 兜底

### 方向 5：干涉与协调检测（台阶 ④ 基础）

**`_detect_clashes` 管道干涉粗检**：
- MEP（管/风管）bbox vs 梁/板/墙 bbox 穿透检测
- 余量 0.05m，排除柱子减少噪音
- **点入网格确认**：不是纯 bbox 误报——用 Möller-Trumbore 射线法，在交叠区域采样点验证真穿透
- office_3f 每层检出设计冲突 ClashPipe→梁 深 0.1m（真阳性）

结果页"潜在冲突候选（粗检）"展开器，带确认标记。

### 方向 6：规则平台化（台阶 ⑤ 基础）

**5 个专业规则集**（之前只有 2 个）：
- 建筑消防 civil / 电气 eee / 结构 structural / 机电 mep / 无障碍 accessibility
- 中国 / 新加坡双标准

**条文 → 机器规则生成器**：
- 给 LLM 一段规范条文 → 自动转成引擎可用的 JSON 规则
- 约束：field 必须从真实字段选（不能造字段名）、code_ref 不编条款号（只写标准名）
- 生成后人工确认，再 `--apply` 追加到规则文件
- 脚本：`scripts/rag_kb/generate_rule_from_clause.py`
