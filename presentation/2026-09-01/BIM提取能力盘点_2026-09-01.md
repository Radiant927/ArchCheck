## 一、整体架构

```
IFC 文件
  │
  ▼
bim/parser.py  ── 解析 IFC 结构（楼层/空间/构件/关系）
  │
  ▼
bim/extractor.py  ── 提取结构化数据
  │  ├── _pipe_data()          → 管道
  │  ├── _duct_data()          → 风管
  │  ├── _electrical_equipment() → 电气设备
  │  ├── _structural_sections()  → 结构构件
  │  ├── _space_to_room()       → 房间
  │  ├── _building_fire_stats() → 全楼消防统计
  │  └── 几何计算函数 → 面积/体积/距离/坡度
  │
  ▼
build_review_data()  ── 组装成审查引擎可用的数据
  ├── building_params（全楼参数）
  ├── floors[].rooms（房间列表）
  ├── floors[].pipes（管道列表）
  ├── floors[].ducts（风管列表）
  ├── floors[].structural_elements（结构构件列表）
  ├── floors[].electrical_elements（电气设备列表）
  └── floors[].clashes（冲突粗检列表）
```

## 二、能做的（已实现）

### 2.1 房间级提取（17 个字段）

| 字段 | 提取方法 | 填充情况 |
|---|---|---|
| `name`, `id` | IFC 直接读取 | 全部 |
| `type` | 名称关键词分类（Office/Corridor/Stairwell/Meeting Room/Equipment Room/Vestibule/Unknown） | 全部 |
| `room_area_sqm` | 几何凸包 → 三角投影求和（**凹形正确**，L 型 27 vs 凸包 36） | 全部 |
| `exit_count` | 关联门的数量 | 有门模型 |
| `door_width_m` | 属性→名称→几何 bbox 三级回退 | 有门模型 |
| `corridor_length_m` | 走廊房间邻接图 → Dijkstra 最远距离 | 走廊 |
| `has_emergency_light` | 房间内应急照明灯具近邻 | 有电气设备 |
| `max_room_travel_dist_m` | 凸包顶点 + 粗网格采样 → 到最近门距离 | 有门+几何 |
| `has_sprinkler` | 消防管近邻近似 | 有消防管 |
| `has_exit_sign` | 房间内疏散指示灯具 | 有电气设备 |
| `eee_src` | 属性声明（"model"或"default"） | 全部 |
| `dist_to_water_m` | 属性 | 有参数 |
| `circuit_load_a` | 属性 | 有参数 |
| `outlet_spacing_m` | 属性 | 有参数 |

### 2.7 几何计算能力

| 计算 | 方法 | 精度 |
|---|---|---|
| 房间面积 | 三角投影求和 | 凹形正确，全精确 |
| 结构体积 | 有符号四面体 | 柱/梁/板已验证 |
| 疏散距离 | 邻接图+Dijkstra + 几何采样 | 走廊级+房间级 |
| 消火栓间距 | bbox 中心最近邻 | **新增**，近似 |
| 竖向排水管径 | 几何 z 向为主判定 | 有几何即可 |
| 坡道坡度 | 属性+几何 | 构件级 |
| 冲突检测 | bbox 穿透 | 粗检（余量 0.05m）|

### 2.8 混合单位处理

- 自动检测 IFC 长度单位（mm/m）
- 交叉校验几何量级（声明 mm 但构件米级 → 用米，如 Schependomlaan）
- 楼层标高单独归一化

## 三、还不能做的（诚实标注）

### 3.1 模型本身没有的 → 算不出来

| 缺失数据 | 影响规则 | 原因 |
|---|---|---|
| 防火分区 (`IfcZone`) | CIVIL-011 防火分区面积 | 提取器不读 IfcZone，建筑模型通常也不写 |
| 照度 (`illuminance_lx`) | EEE-008 应急照明照度 | 模型不带此属性 |
| 耐火等级 (`fire_rated`) | EEE-009 消防配电箱耐火 | 模型不带此属性 |
| 无障碍设施 | ACC-001~005 | 模型不带无障碍厕所/停车/电梯/坡道属性 |
| 消火栓位置 | MEP-009（阶段 A 已近似） | 真实位置需管道拓扑 |

### 3.2 提取器有待提升的

| 问题 | 影响 | 当前状态 |
|---|---|---|
| Duplex 房间-门关联失效 | 0/42 疏散距离算不出 | 模型无门（纯机电），不是 bug |
| **Schependomlaan 门-房间关联** | **6/100 → 98/100 有疏散距离** | **已修**：bbox 矩形占用面 + 放置矩阵旋转 + 边界优先 |

| IfcZone 不读 | 防火分区相关规则全停 | 新的提取任务 |

### 3.2b 门-房间关联修复原理（2026-09-01）

Schependomlaan 有 100 个房间，但 94 个只有 `IfcBoundingBox`（无实体几何网格），旧代码对这些房间返回"无占用面"，门关联和疏散距离全部算不出（6/100）。本次修复三层：

1. **bbox → 矩形占用面**：把 `IfcBoundingBox` 的 X/Y 尺寸放到 `ObjectPlacement` 位置上，得到房间的近似矩形足迹（model 单位）。
2. **放置矩阵（含旋转）**：不能只加位置偏移——Schependomlaan 的楼层框架旋转了 90°，bbox 的 X/Y 在世界坐标里会互换。用 `ifcopenshell.util.placement.get_local_placement` 取完整 4×4 矩阵（沿 `PlacementRelTo` 链合成，含旋转/镜像），把 bbox 四个角变换到世界坐标。
3. **混合单位**：bbox 用声明单位（mm），实体几何用米级（`_length_scale` 交叉校验后为 1.0）。新增 `bbox_scale = 声明单位/scale` 转换（Schependomlaan = 0.001）。
4. **边界优先**：`_associate_doors` 只对"没有 `IfcRelSpaceBoundary` 门数据"的房间跑几何近似——有精确边界数据的房间不再叠加几何近似（否则门数虚高，如某大厅 2 扇真实门被算成 17）。

**验证结果：**
- 疏散距离（`max_room_travel_dist_m`）：6/100 → **98/100**
- 门宽 / 出口数：98/100
- 6 个有真实几何的房间仍用精确凹形面积（20.3 vs 矩形高估 23.4，无误判回归）
- 其余 3 个样例（FZK 5/7、office_3f 24/24、Duplex 0/42 无门）不变
- 新查出 2 条真实违规：房间 3.04 / 6.04 无疏散门（此前"未检查"，现在判定）
- 平面图渲染：bbox 房间首次画出真实足迹（此前一片空）

## 五、提取器架构示意

```
parse_model(m, path)
  │
  ├── 单位检测（_length_scale）
  ├── 楼层遍历
  │   ├── 结构构件提取（_structural_sections）
  │   ├── 门宽提取（_door_width_m）
  │   ├── 房间提取（_space_to_room）
  │   │   ├── 几何面积（_space_area_m2）
  │   │   ├── 门关联（_associate_doors）
  │   │   ├── 疏散距离（_compute_travel_distances）
  │   │   ├── 最远点距离（_max_room_travel）
  │   │   └── 电气参数（属性读取）
  │   ├── 管道提取（_pipe_data）
  │   │   ├── 类型/管径/坡度/长度
  │   │   └── 消火栓间距（新增）
  │   ├── 风管提取（_duct_data）
  │   ├── 电气设备提取（_electrical_equipment）
  │   ├── 冲突粗检（_detect_clashes）
  │   └── 平面图元素（_plan_elements）
  │
  └── 全楼消防统计（_building_fire_stats）
        └── 电梯/灭火器/喷淋/报警

build_review_data(struct)
  └── 组装字典 → 喂给 core/engine.py
```

## 六、下一步可以做的提取工作

按优先级排列：

1. **IfcRamp 提取 → building_params** — 简单，已有 `_ramp_slope` 函数，只需写入 `max_ramp_slope`

4. **IDS 驱动提取** — 用 IDS 反过来要求"提取器必须读什么"，台阶 2 的关键路径
5. **门-房间关联优化** — ~~6/100~~ **已完成**：bbox 矩形占用面 + 放置矩阵旋转 + 边界优先 → 98/100（详见 3.2b）
