## 二、L1 主线：互检出报告 → viewer（导师路线落地）

### 核心缺口（现状 vs 已有，避免重复造轮子）

- 已有：benchmark D 轴 = **合理性代理**（`benchmark_ifc.py` 自己写明 "not a ground-truth comparison"，只判断尺寸落在合理范围，不能回答"这根管到底读没读对"）。
- 已有：`scripts/diagnose_geometry_accuracy.py` 雏形 —— 用 ifcopenshell 从 IFC **原始几何直读**（墙高=拉伸深度、墙厚=profile bbox）当真值，再比提取值；但只覆盖官方 wall-with-opening 单模型，参考值部分硬编码。
- 缺：一份**逐实例对/错/漏清单**，每行 = `(构件 GlobalId, 类别, 字段, 文件真值, 提取值, 判定 ✓/✗/漏, 根因归类)`。有了它才有"哪对哪错"可讲，也才能给 viewer 当标注数据源。

### 真值的三档来源（按可信度）

1. **文件原始**（主力）：ifcopenshell 直读几何/Qto/属性，作真值近似 —— 已实现，扩展即可；
2. **buildingSMART 官方公布值**：ReferenceView 样例的墙 2.0m / 窗 1.0×1.0 这类 —— 外挂成数据表，不只硬编码在脚本里；
3. **人工复核**：真实模型（FZK 等）抽 N 个构件人工在建模软件里量，抽样校验直读真值本身可信。

### 分步（每步含产出与验收）

**A1 · 互检口径定版（半~1 天）**
把 `diagnose_geometry_accuracy.py` 输出从"逐字段散点"升级为"逐实例对错清单"：
- 记录列：GlobalId / 类别 / 字段 / 文件真值 / 提取值 / 判定(✓✗漏) / **根因标签**（单位换算 / 坐标轴取错 / profile 截面 / fallback 估算 / 类型映射 / 根本没读）；
- 产出：`output/crosscheck/互检清单_<模型>_<日期>.csv`；
- 验收：每根因标签能下钻到 extractor 的具体函数。

**A2 · 首批金标准模型跑通（本周，→09-15 汇报的"哪对哪错"证据）**
- 模型选 2 个：官方 `ReferenceView/wall-with-opening-and-window.ifc`（有公布值）+ FZK-Haus（真实、B=100、逐构件全读，可当"读全"样板）；
- 把已曝光的"读漏/读错"当 bug 单挂进清单（例：官方样例 **slab 3 块只读 1 块** → B 掉到 66.7，三版本一致 = 提取器对这类楼板几何的固定缺口）；
- 产出：互检 v1 报告（md），含 ✓ 率 + 根因分布 + 待修 bug 单；
- 验收：报告可读给老师听：*"这一行 = 墙 #123，文件里 0.3m，我们读到 0.3m ✓；那一行 = 板 #456，漏读，根因是……"*

**A3 · 修最高频读漏/读错（下一周）**
- 以 A2 bug 单 + `diagnose_entity_coverage.py` 的 `entity_coverage_gap` + B 轴缺口为输入，挑影响最大的 2~3 个根因修（slab 首当其冲）；
- 产出：extractor 代码变更 + 互检清单 ✓ 率回升对比；
- 验收：同一互检清单重跑，✓ 率上升可量化。

**A4 · 互检扩维 + 铺到 7 个 S/A 真实模型（中期）**
- 从"几何尺寸"扩到三维：**计数**（对照 by_type 真值，现 B 轴）、**分类**（pipe_type/room type，对照 system 名/房间名）、**属性**（Pset 值，对照 IfcRelDefinesByProperties）；
- 7 个真实建筑模型（HITOS/FZK/Smiley-West/Institute/Jasmin/Basic/MEP Sample）全覆盖；
- **人工复核策略（分层抽样，不做全量、不做纯随机）**
  - 样本量：每模型 100~150 个（统计学上支撑可信度，1~2 天可完成）；
  - 80% ≈ 120 个按类别均匀分配：墙/板/柱/梁/管/风管/配件等，每类都有样本；
  - 20% ≈ 30 个高危样本：定向抽 A2 阶段发现的高频读漏/读错类型（比如 slab 总漏就读板）；
  - 复核维度：不仅看个数，更看核心属性（尺寸、材质、系统类型）是否与文件直读一致。
- 产出：互检清单覆盖 7 模型 + 每模型一份对错汇总 + 分层抽样复核表；
- 验收：每个 S/A 模型 ≥95% 逐字段 ✓ 或有根因归档，人工复核无新增重大漏读。

**A5 · viewer 起步：静态标注 → 交互（L1 终点，跨期）**
- 起点盘点：parser 已能画房间足迹（bbox 房间已画出真实 footprint）、已有 `scripts/export_bcf.py`；
- 第一阶段先做**静态标注图**：把互检清单的 id/尺寸标到几何上（读到 0.3m/实际 0.3m ✓ 用同色；漏读红标），一张图能展示"对/错/漏"分布 —— 这本身就是 09-15 之后最直观的汇报素材；
- 第二阶段交互：选构件 → 显示 提取值 + 真值 + 触发了哪条规则 + 该规则条文引用；
- 产出：标注 viewer 原型（先静态逐模型 → 后交互）；
- 验收：老师能在图上指出任意构件，看到它的提取值与审查结果。

## 三、L2 收敛线：按规则补数据（规则激活率 33 → 60+）

> 已有进展（09-08 轮完成）：pipe_type 回填（识别率 29%→86%，MEP 激活 6/13→9/13）、room type 增强（LongName+多语言）、几何合理性评测修正（发现几何本身 96-99% 合理）、实体类型 +6（栏杆/基础/卫生器具/风口/插座全读对）。

**B1 · 无障碍几何推断收尾（高价值，半~1 天/条）**
- ACC-003 走廊净宽已活（Smiley-West 40 条走廊可判）；续推从几何/房间类型推断 → 坡道宽度（ACC-005）、无障碍卫生间（ACC-001）；
- 产出：无障碍激活 0~1/5 → 3/5；
- 验收：推断规则与上一轮走廊净宽同一套（bbox/几何近似），判定不误报。

**B2 · EEE 编辑器闭环（不硬激活，1 天）**
- 定位（**作为 feature 讲，不讲"做不到"**）：EEE 6 条所需属性（照度/回路负荷/耐火等级）IFC 建模大多不带，纯自动阶段不激活不是能力不足，而是**有意为之的疑似项推荐机制**——硬规则（diameter < 10mm 就报错）在工程中极易误报（仪表管、毛细管），海量噪音会让用户不信工具。
- 价值闭环：系统负责**筛查（Filter）**，把疑似问题挑出来；人负责**决策（Decision）**，凭专家经验判定是否违规。EEE 编辑器是这个闭环的入口：用户补 `ArchCheckEEEEquip` Pset → 6 条规则激活重判 → 形成"算法推荐 + 人工确认"的完整回路。
- 产出：补 Pset 后重审 6 条 EEE 全活的演示路径；
- **09-15 汇报话术建议**：
  > "为了解决传统 BIM 审查误报率高、噪音大的痛点，我们采用疑似项推荐机制。对几何边界模糊或存在争议的死规则，系统不武断直接报错，而是标记为待确认，引导用户在 EEE 编辑器中基于专家经验二次判定。这种智能筛选 + 人工专家闭环的模式，更适合复杂工程场景。"

**B3 · 知识库规则本身（跟随 L1 A3 的读漏修复）**
- Q2 目标值 33→60+ 主要靠"数据喂饱"而非加规则；随 A3 修的读漏与 B1 的几何推断自然上升；
- 诚实边界写进报告：EEE 是数据源问题（编辑器补），IFC2X_FINAL/基础设施是平台定位外，不做。

## 五、风险与汇报口径

- 互检的"真值"本身有近似性（几何直读不是建模软件里的属性表），A2 抽少量人工复核兜底，别把近似当真值吹；
- slab 只读 1/3 这类缺口三版本一致 → 是好素材（证明互检能晒出固定 bug），也是要修的真 bug；
- **EEE 死规则**：定位成 feature（疑似项推荐 + EEE 编辑器闭环），不回避、不示弱；详见 B2。
- **无障碍死规则**：先靠几何推断激活 3/5 条，剩余明确归因"模型缺无障碍属性 = 如实标 Missing"，不硬凑。
