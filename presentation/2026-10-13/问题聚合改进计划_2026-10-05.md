# 问题聚合改进计划：从"500 条刷屏"到"20 条摘要"

> 日期：2026-10-05
> 背景：跑了 6 个基准模型，发现三大系统性呈现问题（单条规则刷屏 / Missing 混入 / 无摘要视角）
> 目标：不改变审查判定逻辑，只改变呈现方式，让用户第一眼看到重点
> 红线：**确定性规则判定 100% 不变**，改的只是结果组织与展示

---

## 一、问题诊断（基线数据）

跑了 6 个代表性模型（FZK / office_3f / Duplex_MEP / Schependomlaan / HITOS / Smiley-West），系统性问题三个：

| 问题 | 表现 | 典型数字 |
|------|------|----------|
| **单条规则刷屏** | 一条规则触发几百条，占总问题 30-45% | Duplex 的 MEP-013 一条 279 条 = 44.6% |
| **Missing 混排** | 数据缺失不是"违规"，但和真实违规混在一起 | 平均 24-37% 的"问题"其实是 Missing |
| **没有摘要视角** | 用户得翻几百条自己找重点 | HITOS 757 条里找 High 风险，得翻屏 10+ 次 |

**典型痛点**：
- "左边柱子右边柱子都不合适，明明一个总结就行，分成几十条"
- "打开一看 700 个问题，不知道从哪看起"
- "很多地方空白 / 读不到数据，全是数据缺失"

详细基线数据见：`基准模型审查数据_2026-10-04.md`

---

## 二、改进方案（三层递进）

### 第一层：聚合 + 折叠（主攻，1-2 天）

**核心改动**：问题列表从"逐条平铺"改为"按规则聚合，默认折叠"。

#### 1.1 聚合维度

按 **rule_id × floor × system** 三级聚合：

```
聚合键 = (规则ID, 楼层, 系统/类型)
```

- 结构类：`(STR-003, "1F", "wall")` → "1 层 12 面墙厚度不足"
- MEP 类：`(MEP-013, "2F", "hydronic")` → "2 层供暖系统 35 根管缺坡度标注"
- 建筑类：`(CIVIL-004, "3F", "room")` → "3 层 8 个房间疏散走道宽度不足"
- 建筑级规则（BLD-*）：不展开，每条一个卡片

聚合卡片显示：
- 严重度（取该组最高）
- 规则 ID + 名称
- **影响数量**（X 个房间 / Y 根管道 / Z 根柱子）
- 分布（各楼层数量概览）
- 一个"展开"按钮，展开后才显示逐构件明细

#### 1.2 Missing 独立分区

把数据缺失从主问题列表里拿出来，放到独立的**「模型覆盖度」**区域：

- 真实违规（High/Medium/Low）→ 主区域，按聚合卡片展示
- 数据缺失（Missing）→ 「模型字段覆盖率」区域，按规则聚合展示
- 未检查（NotChecked）→ 同上区域，保持现有聚合形态

顶部加一个一句话总览：

> 📊 本模型共发现 **28 类审查意见**，影响 **147 处具体位置**。其中高风险 6 类、中风险 8 类、低风险 14 类。另有 **7 类规则因模型缺少字段无法检查**（影响 210 个元素）。

#### 1.3 预期效果

| 模型 | 原始问题数 | 聚合后卡片数（预估） | 压缩比 |
|------|-----------|---------------------|--------|
| FZK | 29 | ~12 | 2.4× |
| office_3f | 57 | ~14 | 4.1× |
| Duplex_MEP | 625 | ~20 | 31× |
| Schependomlaan | 495 | ~18 | 27× |
| HITOS | 757 | ~25 | 30× |
| Smiley-West | 267 | ~15 | 18× |

**首屏体验**：从"满屏 Low/Missing 刷屏" → "一眼看到全部 High 风险 + 中风险摘要"

---

### 第二层：多视角切换（3-5 天）

在聚合基础上，增加**视角切换**，用户可以从不同维度看问题：

```
[ 按规则看 ▾ ]   按楼层看   按系统看   按房间/位置看
```

#### 2.1 按规则看（默认，第一层已实现）
- "这条规则影响了哪些地方"

#### 2.2 按楼层看
- 每个楼层一张卡片："3F 共 5 类问题 / 23 处"
- 展开看该楼层的全部违规

#### 2.3 按系统看（MEP 专项）
- 消防系统 / 排水系统 / 供暖系统 / 通风系统 各一张卡片
- 适合 MEP 工程师按专业审图

#### 2.4 按房间/位置看
- 每个有问题的房间一张卡片："105 会议室 共 3 项问题"
- 展开看该房间的全部违规（疏散 + 电气 + 无障碍...）
- 最接近传统审图意见的形态

---

### 第三层：智能摘要（中期，AI 辅助）

在确定性聚合的基础上，加一层 AI 语义摘要：

#### 3.1 Top 5 优先级
- 综合严重度 × 影响范围 × 修复成本，自动排"最该先改的 5 个问题"

#### 3.2 语义聚类
- "这 8 条问题都属于'疏散路径不达标'组"
- "这 15 条都是'结构构件尺寸偏小'组"

#### 3.3 自然语言摘要
- 一段 3-5 句话的整体评价，类似审图师的初审意见

> 红线守住：AI 只做摘要和排序，不改变任何一条判定。

## 三、技术实现路径

### 改动范围

| 模块 | 改动量 | 说明 |
|------|--------|------|
| `core/engine.py` | 小 | 加一个聚合函数 `aggregate_issues(issues)`，不碰 run_rules |
| `core/report.py` | 中 | 导出报告支持聚合视图 |
| `app.py` | 中-大 | 问题列表 UI 重写：聚合卡片 + 展开明细 + 视角切换 |
| `core/i18n.py` | 小 | 加几个聚合相关的文案 |
| 规则 / 判定逻辑 | **零** | 红线：判定一字不改 |

### 核心函数设计

```python
# core/engine.py 新增
def aggregate_issues(issues, group_by="rule"):
    """
    将逐构件问题聚合为高层卡片。
    
    group_by:
      - "rule":    按规则聚合（rule_id → floor → system）
      - "floor":   按楼层聚合（floor_name → rule_id）
      - "system":  按系统聚合（system → rule_id）
      - "room":    按房间聚合（location → rule_id）
    
    返回: [
      {
        "group_key": "CIVIL-004",
        "title": "疏散走道宽度不足",
        "severity": "Medium",  # 组内最高
        "count": 23,
        "scope": "room",
        "by_floor": {"1F": 8, "2F": 7, "3F": 8},
        "items": [...]  # 原始问题列表，供展开
      },
      ...
    ]
    """
```

### UI 结构

```
问题总览卡片（1 行）
├─ 真实违规 N 类（High X / Medium Y / Low Z）
└─ 未检查 M 类（影响 K 个元素）

[ 按规则 | 按楼层 | 按系统 | 按房间 ]  视角切换

严重度筛选：[全部] [高] [中] [低] [未检查]

聚合卡片列表（默认折叠）：
├─ 🔴 CIVIL-012 · 疏散距离超限 · 6 房间（1F×2 / 2F×2 / 3F×2）  [展开]
├─ 🔴 MEP-004 · 风管净高不足 · 3 根（1F 通风系统）             [展开]
├─ 🟡 STR-002 · 柱截面高度偏小 · 57 根（1F×22 / 2F×20 / 3F×15） [展开]
├─ 🟢 MEP-013 · 管道坡度标注 · 279 根（供暖×164 / 给水×145 ...） [展开]
└─ ...
```

## 四、验收标准

用 6 个基准模型回跑，验证：

### 功能验收
- [ ] 6 个模型的审查判定 **一字不变**（逐构件的 rule_id / severity / 位置完全一致）
- [ ] 聚合后卡片数明显减少（压缩比 > 5× 对于 >200 条的模型）
- [ ] 高风险问题全部在首屏可见（无需滚动）
- [ ] Missing 问题不出现在主违规列表中
- [ ] 点击"展开"能看到完整的逐构件明细
- [ ] 4 种视角切换都能正常工作（第一层只做"按规则"，第二层补齐）

### 体验验收
- [ ] 用户 3 秒内能回答"这个模型最严重的问题是什么"
- [ ] 用户 3 次点击内能看到"某一层 / 某一系统 / 某一房间的全部问题"
- [ ] 不再出现"几百条全是同一类"的刷屏感

## 五、优先级与排期

| 阶段 | 内容 | 工期 | 优先级 |
|------|------|------|--------|
| P0 | 按规则聚合 + Missing 分区 + 总览卡片 | 1-2 天 | 最高 |
| P1 | 按楼层 / 按系统 / 按房间 视角切换 | 2-3 天 | 高 |
| P2 | 严重度筛选 + 搜索框 | 0.5 天 | 中 |
| P3 | AI 智能摘要 / Top 5 推荐 | 3-5 天 | 中（看老师意见） |

**建议先做 P0**，一天左右能出效果，demo 给老师看了再决定要不要往下做。
