# BIM 读取精准度提升记录（三阶段：v1 → v2 → v3）

> **问题缘起**：任意模型都刷出大量"问题"，其中大量是同类重复，且许多地方读不到数据 / 显示空白。
> **测评设计**：同一套 6 个基准模型、同一套规则集，只更换平台版本，逐模型对表。
> **红线**：非目标规则判定逐条零回归（`NON-TARGET REGRESSIONS: 0`），即删掉的全部是误报，真问题一条不丢。
>
> **三阶段演进**：
> - **v1（2026-10-04）**：修复前基线
> - **v2（2026-10-06）**：精准度修复（误报大清洗）
> - **v3（2026-10-12）**：MEP 能力补齐 + 互检 + benchmark 工具链（新增，见文末追加节）

## 四、提升点归类（三层）

### 第 1 层：判得对 —— 消除三类系统性误报

1. **全楼规则不再跑硬编码默认值**（病根 A）
   - 旧：层高 2.4m / 消防水量 160 / 变压器 650 / 应急时长 60min 是写死的，每楼必产生 4 条幽灵问题（BLD-001/002/003/004）。
   - 新：从 IfcProject/IfcSite/IfcBuilding 的 pset 读真实设计值，模型没声明 → 未检查。
   - 佐证：office_3f 真声明了 3.6m/216/750，BLD-001/002 正确**通过**；仅 BLD-004（真写 60<90）保留。

2. **结构规则加材料过滤 + 剔除非结构构件**（病根 B）
   - 新增 `material_class`（wood/steel/masonry/concrete，多语言；修正德语 `Stahlbeton` 被误判为钢 → 正确归 concrete）。
   - 钢/木构件不再套混凝土最小截面阈值（STR-001/002/004）。
   - 吊顶、找平层、岩棉保温、栏杆等通过 `_NONSTRUCT_KEYS` 移出结构构件集，不再被当结构板审查。

3. **"模型没建"不再当违规**（病根 C）
   - 应急照明、喷淋、火灾报警、消防电梯/灭火器数量：仅在模型显式表达时才判定，否则未检查（CIVIL-006、BLD-007/008/009）。
   - MEP-013 按规则本意限定"未知系统管道"：Duplex 279→8，office 消防管 9→0。

### 第 2 层：读得懂 —— 语义识别增强

- 新增多语言材料识别（含钢筋混凝土 vs 钢的关键消歧）。
- 能区分结构板 vs 吊顶 / 找平 / 保温 / 瓷砖 / 防水层，结构构件集更"干净"。

### 第 3 层：读不到时更诚实

- 旧：字段缺失要么显示空白、要么被当违规；新：统一归入「未检查（缺字段）」，用户能区分"模型没提供"与"不合格"。

## 五、经核实保留的"真问题"（证明不是靠放水降数量）

- **EEE-001**：office_3f 显式声明 `has_emergency = IFCBOOLEAN(.F.)`（#2385），应急照明确缺，保留 High。
- **CIVIL-007**：HITOS 51 个房间经几何核查确实未建同层疏散门（198 扇门质心全部有效；阈值外的门最近空间都是别的房间；x-y 重合的门 z 差 ±4m 属别的楼层），保留 High。
- **STR-001**：HITOS 30 → **12**（2026-10-09 第三轮再核）。原 30 条中 7 根是 1000×200mm 剪力墙（类型选错为 IfcColumn）、11 根是无 Name/无材料的匿名 ArchiCAD 导出残留——二者均移出柱审集；剩 12 条为真承重细柱（4×BS04 150×350 + 8×BS02 200×200），保留。其余模型逐规则零回归。

## 六、本次"没有"提升的部分（口径说明，勿夸大）

- **底层几何尺寸的测量精度这一轮未改动**（PCA/bbox/拉伸轮廓提取逻辑不变），属路线图"精确几何"方向。
- **模型本身未建模的内容，平台无法凭空读出**——这是输入数据的 LOD 上限，不是软件缺陷；平台能做的是诚实标"未检查"。

## 八、追加：v3（2026-10-12）MEP 补齐 + 工具链建设

> 这一阶段的主线不是"继续压误报"，而是**把能力边界向外推**：MEP 从"能看"变"能用"，
> 同时建立了互检和 benchmark 两套度量工具，让以后每一步改进都能量化。

| Duplex_MEP | 188 | 188 | 0 |

**逐指标核对（6 模型全部一致）**：Missing 条数、未检查规则数、涉及规则数三项，v3 与 v2
**逐一相等**（8/25/7、21/16/9、150/36/10、180/31/7、280/22/10、100/26/4）。
唯一变化是 HITOS 的 STR-001：第五节已记录的 10/9 第三轮核查把 7 根误标为柱的剪力墙 +

即：本周工作是**纯增量**，已有判定一条未动。

### 本周新增四大能力（v3 独有）

#### 1. MEP 机电审查能力补齐（6 项）

| 能力 | 说明 |
|------|------|
| 管道网络拓扑读取 | 读端口 / 系统归属，用系统名回填管型 — 不再把管道当孤立圆柱 |
| MEP 提取增强 | 配件 / 数量集 / 材料 / 系统分类 + Qto-Profile 单位抽样推断 |
| 消火栓间距激活 | MEP-009 从消防管 bbox 中心算间距，首次产出真实判定 |
| MEP 普适兜底规则 | 未知系统管道按通用管径 / 坡度 / 净空审查，不再"未检查" |
| Clash 检测 11× 提速 | bbox 缓存；Lab.ifc 49s → 4.4s，结果完全一致 |
| 实体覆盖度上报 | QA 报告加"模型有但我们没读的类型"，如实告知边界 |

#### 2. 逐构件互检工具 crosscheck

- 新增 `scripts/crosscheck_ifc.py`：IFC 直读真值 vs 提取器输出，**逐构件比对**
- 输出 ✓/✗/漏/多 + 根因标签；三档真值（官方公布 / 文件直读 / 人工复核）
- 同名多实例按几何中心就近匹配；混合单位用 world_scale 校准
- 附带修复：斜板斜梁厚度（Qto→Extrusion→PCA→bbox 降级链）、英制单位校准、footing/栏杆/楼梯逐件修复

#### 3. 六维测评框架 benchmark_ifc.py

- 新增 `scripts/benchmark_ifc.py`：每个模型跑完整管线，6 轴加权打 S/A/B/C/D 级
  - A 健壮性 20% / B 提取完整率 25% / C 字段填充率 20% / D 准确性代理 15% / E 规则激活率 15% / F 性能 5%
- 输出单模型 JSON + 批量 summary.csv（utf-8-sig 供 Excel）
- **意义**：以后任何改进都能量化"提升了多少"，不再靠感觉

#### 4. 几何提取修复（crosscheck 驱动）

- 斜板 / 斜梁 / 网格板厚度不用 bbox Z 差（那是屋脊高差），改走 Qto → ExtrusionDepth → PCA 最小主轴降级链
- Revit mm 声明板厚 ~1000× 偏差：Qto/Extrusion 用声明单位，PCA/bbox 用世界单位，profile_scale 不可信时不混用
- 结构构件 cap 30→500；footing 走 PCA 截面（桩不再被厚度过滤丢弃）
- 未包含墙门窗按 z 归属楼层的 fallback

### v3 诚实边界

- **底层几何尺寸的毫米级精度仍未改动**（PCA/bbox/拉伸轮廓提取逻辑不变）
- crosscheck 当前验证"几何有无 + 大致位置 + 尺寸 sanity"，还没到"属性级逐项核对"
- MEP 兜底规则是下限，精确审查仍需具体系统类型
- benchmark 是"读取完备性"度量，不是"审查准确性"度量 — 准确性靠 crosscheck
