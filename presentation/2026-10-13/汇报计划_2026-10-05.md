### Part B · 主线 1：提取完备性（3 页）

**P3 · 为什么需要 benchmark —— 之前的问题**
- 之前不知道"我们漏读了多少"——只有规则 hit 数，没有覆盖度
- 不同模型差异巨大：有的模型 20 类构件，有的 80 类
- → 需要一个**统一的度量衡**

**P4 · 6 维 benchmark 框架（benchmark_ifc.py）**
- 6 个维度：几何完整性 / 拓扑关系 / 属性填充率 / 系统归类 / 单位一致性 / 覆盖度
- 输出：每个模型一张 6 维雷达图 + 分级（S/A/B/C/D）
- 跑过哪些模型（拿 31 个测试集的结果说话）
- 诚实边界：S 级只代表"我们读得全"，不代表"审得对"

**P5 · 提取器增强清单**
- 几何：footing / 栏杆 / 楼梯 逐件修复，B-Rep 兜底
- 拓扑：管道端口 / 系统归属 / 网络拓扑读取
- 属性：配件数量集 / 材料 / Qto-Profile 单位抽样推断
- 单位：英制单位自动识别与换算（解决英制模型全错的问题）
- 覆盖度：未识别实体如实上报为"未检查"（不再假装没看见）
- 性能：clash 检测 bbox 缓存，Lab.ifc 49s → 4.4s

### Part C · 主线 2：逐构件互检（2 页）

**P6 · crosscheck 工具 —— 我们自己的"真值比对仪"**
- 思路：拿"我们提取的构件" vs "权威 BIM 软件数出来的构件"
  - 不是数总数，是**逐件匹配**（名称 + 几何位置就近消歧）
- 三个输出：匹配率 / 漏检 / 多检 / 几何偏差
- 匹配算法：先按 GlobalId 精确匹配，剩的按 bbox 中心距离 + 类型就近消歧

**P7 · 互检结果（FZK + office_3f）**
- FZK：103 构件，100% 匹配（S 级验证模型）
- office_3f：XXX 构件，匹配率 XX%，漏检 XX（哪些类没读到）
- 几何偏差：footing / 栏杆 / 楼梯修复前后对比
- 诚实边界：只覆盖"有几何 bbox 的构件"；纯语义属性（如防火等级）不在这里

### Part D · 主线 3：平面图引擎（2 页）

**P8 · 为什么做平面图 —— 3D 之外的刚需**
- 3D Viewer 很酷，但设计院日常看的是**平面图**
- 审图报告的传统形态就是"图上画圈 + 说明"
- → 把审查结果**画在真实楼层平面上**，是从"工具"到"可用工具"的一步

**P9 · 平面图引擎能做什么（drawing.py + UI 重构）**
- 三种平面视图：
  - **标注图**（静态）：房间轮廓 + 违规点按专业着色 + 图例
  - **交互图**：hover 看详情 / 点击跳问题
  - **互检图**：真值 vs 我们的提取，匹配的绿、漏的红、多的黄
- 配套：建筑剖面图（楼层堆叠 + 竖向问题标注）
- UI 重构：楼层 tab 化 + 每层"问题列表 / 平面图"双视图
- 红线守住：平面几何 100% 来自 IFC 提取，AI 不碰几何

## 四、诚实边界（汇报必须讲准）

1. **benchmark 是"读取完备性"度量，不是"审查准确性"度量**
   - 读得全 ≠ 审得对；审查准确性靠 crosscheck
2. **crosscheck 当前只验证"几何有无 + 大致位置"**
   - 还没到"尺寸精确到毫米"的级别；属性级互检是下一步
3. **平面图引擎是"IFC 几何的 2D 投影"，不是施工图级出图**
   - 用于可视化审查结果，不用于施工出图
4. **MEP 兜底规则是"总比不审强"的下限**
   - 不是精确审查；精确审查需要知道具体系统类型
