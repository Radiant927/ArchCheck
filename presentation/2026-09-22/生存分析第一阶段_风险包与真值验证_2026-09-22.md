# 生存分析第一阶段：独立风险包 risk/ 与真值验证

> 日期：2026-09-22 ｜ 对应项目书《全生命周期预测性合规平台》计划二
> 范围：新建独立 `risk/` 包 + 驱动脚本 + 可复算数字。**不碰审查引擎、app、viewer**，平台零回归。

---

## 1. 这一步要回答的问题

项目书提出用生存分析把合规从"交付当下的快照"延伸到"预测何时不合规"。动工前先回答三个前置问题：

1. 合成数据能否忠实承载 Weibull 生存模型（含协变量效应、右删失）；
2. 从"十年维保记录"里，KM/Cox 能否把真实参数与风险排序学回来；
3. 项目书设想的预测规则（"预测失效日期早于下次检修周期 → 报警"）在统计上是否成立。

## 2. 方法：一句话与一张图

**给管道"算命"，而且自己手里攥着答案。** 生成器造一批管道、知道每根的真实寿命（锁进抽屉），只把十年维保记录交给模型；模型从记录里学规律，再把预测和抽屉里的真值逐件对照。这与平台已有的"逐构件互检验真"是同一方法论。

```
risk/families.py   构件族目录：Weibull 参数 + 协变量效应 + 证据台账
risk/generator.py  合成 400 根管道：协变量 → 真实寿命 → 维保记录/右删失
risk/survival.py   KM 生存曲线 + Cox 比例风险（statsmodels PHReg）+ 预测
risk/evaluate.py   对照真值：参数恢复 / 排序 / 校准 / 预测规则 / 弃权
```

**模型规格（Weibull 比例风险）**

- 基准寿命分布：S₀(t)=exp(−(t/λ)^k)，取 **k=2**（风险随年龄上升，对应锈蚀累积）、**λ=24 年**（基准中位寿命≈20 年）；
- 协变量在 Cox 对数风险尺度上改变寿命：材料（碳钢/镀锌/不锈钢）、系统（给水/消防/暖通/燃气/污水）、环境（干燥/潮湿/地下）、既往维修次数；
- 分析时点 2026-01-01，管龄 0.5–15 年；已失效的给精确失效时间，仍在用的右删失。
- 预测用 Breslow 基线（自算，规避 PHReg 中心化约定），观察期末尾之外用拟合 Weibull 外推。

> 证据等级：以上全部参数目前为 **C 级（合成假设）**，仅用于验证方法学；报送/论文版将以规范与可靠性文献替换，禁止把假设当实测结论。

## 3. 结果：全部数字可复算

主结果 `n=400, seed=7`；稳健性为 20 次独立重复（种子 1–20）的均值。

| 验证维度 | 结果（seed 7） | 20 次重复 |
|---|---|---|
| 事件率（10 年内已失效） | 25.2%（101/400） | 21.5% |
| **β 参数恢复** | 9 个系数 95%CI **全部覆盖真值** | CI 经验覆盖率 0.90–1.00（名义 0.95） |
| **风险排序** C-index | 0.729（潜真值）/ 0.754（观测） | 0.719 / 0.752 |
| 个体中位失效年 MAE | 7.64 年（±2 年 19.0%，±5 年 46.8%） | 8.29 年 |
| KM 正确性（同质人群 vs 真 Weibull，积分误差） | 0.011 | — |
| 拟合基线尾部 Weibull | k=2.10, λ=21.0（真值 2.0/24） | — |

**β 恢复举例（HR = 风险倍数，真值 → 拟合）**：不锈钢管 0.111→0.074、污水管 2.014→2.129、地下环境 4.055→4.698、每次既往维修 1.419→1.431。

### 预测规则的实测：原写法被证伪，换"风险排序分配检修"

在役 295 根，未来 2 年内真实失效 26 根（基础率 8.8%）：

| 规则形态 | 结果 |
|---|---|
| 项目书原写法：预测中位失效年 < 下次检修（2028）→ 报警 | 只报 3 根，**precision 0、recall 0**——中位寿命估计天然偏保守，规则近乎失效 |
| **风险排序：检修资源投给风险最高的 10%** | 命中 13.8%，**lift 1.56**（seed 7）；20 次平均命中 23.8%、**lift 2.71** |
| 先知天花板（用真实模型+真实风险因子排序的 top10%） | 命中率 26.6% → **拟合模型已达天花板的 89%** |

## 4. 关键结论（三个认知更新）

1. **统计管线成立**：β 可恢复（CI 覆盖）、风险排序有效（C-index≈0.72）、拟合模型逼近先知上限（89%），方法学可以进引擎。
2. **"全员二元报警"在该场景天然弱**：即便用真实模型，2 年窗口内的个体失效也主要由 Weibull 随机性决定——top10% 命中率上限只有约 27%。预测规则应改为**按风险排序分配检修资源**（这也正是业界做法），而不是给每根管道判"报/不报"。
3. **抬天花板靠状态监测协变量**：壁厚测量、锈蚀传感器等在线监测信息能显著提高短期可预测性——量化"加 IoT 监测后 lift 提升多少"的实验已列为下一步，直接对接城市生命线"动态监测、预测预警"叙事。

**诚实机制**：样本 n=15（仅 1 起失效）时管线自动弃权、不出任何构件级预测；参数证据等级随结果记账，C 级假设不冒充文献。

## 7. 未来能做的方向（路线图）

四个方向，按"先把论文亮点做厚 → 再端到端落地 → 报送前补证据"排序。每个方向给出做法、改动文件与验收标准。

### 方向一（推荐先做）：状态监测协变量实验——IoT 能把预测力抬多少

**问题**：第一阶段证明静态协变量下短期可预测性有天花板（top10% 命中率上限约 27%）。壁厚测值、锈蚀在线监测等状态信息能打破这个天花板吗？提升量与传感器精度、监测频率的关系是什么？

**做法**
1. 在生成器里引入**与潜失效过程同源**的物理量：腐蚀深度按幂律 d(t)=a·t^n 增长，失效=深度触及随机临界深度（Weibull 分布即由此而来）；
2. 三种监测体制对照：无监测 / 检修期一次壁厚抽检（含测量噪声）/ 在线传感器连续监测；扫描噪声水平与监测频率；
3. 指标同第一阶段：top5/10/20% 命中率与 lift、C-index，并与各体制各自的"先知天花板"对比，画出"信息量—预测力"曲线。

**改动文件**：`risk/families.py`（监测配置块）、`risk/generator.py`（腐蚀过程与测值生成）、`risk/evaluate.py`（监测对照实验）、`scripts/risk_pipeline.py`（`--monitor none/inspection/sensor --noise`）、新输出 `output/risk/monitoring_*.json`。

**验收**：lift 随监测信息量单调上升且可用真值复算；产出"每提高一档传感器精度/频率，top10% lift 增加多少"的定量曲线——这就是城市生命线"IoT 动态监测价值"的直接证据，也是论文核心实验之一。

### 方向二：预测规则进引擎（第二阶段）

**问题**：把验证过的风险模型接进确定性审查闭环，且守住"规则负责判、数据不足就弃权"。

**做法**
1. 引擎在"即时违规 / 缺字段未检查"之外新增第四类判定 **severity=Predictive**：输入为构件 `p_fail_cycle`，规则形态按第一阶段结论采用"**超概率阈值预警 + 风险排序检修清单**"，而非中位寿命二元报警；
2. 无维保数据的构件报"未检查（缺维保数据）"，走现有 NotChecked 折叠机制，绝不编造寿命；
3. `bim/extractor.py` 给 pipe dict 补 `global_id`（当前无此字段），使风险预测可逐件挂到真实构件；app 增加维保数据入口（可直接吃第一阶段导出的维保日志/预测 JSON）；
4. i18n 增 Predictive 相关中英词条，报告计数与筛选同步；后续按族配置加防火门下垂、喷头堵塞两个新族。

**改动文件**：`core/engine.py`、`core/i18n.py`、`core/report.py`、`app.py`、`bim/extractor.py`、`data/standards/{cn,sg}/`（新增预测类规则）、`risk/`（预测导出接口）。

**验收**：FZK / Revit-MEP 端到端跑通——高风险管段在列表与三维中可定位，缺维保数据显示"未检查"；新增数字固定种子可复算；**原有 demo 审查计数不变**（零回归红线）。

### 方向三：4D 风险演化 viewer（第三阶段）

**问题**：把"风险在哪里 × 何时发生"收成一个统一场景。

**做法**
1. viewer 加时间轴滑块（2026→2036），构件颜色随该年份 hazard 由绿变红；
2. 点击构件同时展示：当前规范符合性 + 预期失效年份 + 建议检修窗口 + 规范依据；
3. 复用现有三 iframe + postMessage 桥与 bbox 约定（见 3D viewer 架构）；`web/serve.py` 增 `/api/risk` 返回按 GlobalId 的逐年 hazard。

**改动文件**：`ifc-demo/main.js`、`web/serve.py`、`web/viewer_bridge/`、`app.py`（结果页挂时间轴）。

**验收**：FZK 流畅拖动、颜色逐年更新、点击信息面板正确；Revit-MEP 量级可拾取不卡死。

### 方向四：证据锚定（报送/投稿前并行必做）

1. 用规范与可靠性文献替换全部 **C 级参数**（管道寿命 Weibull 分布、锈蚀速率、检修周期），证据台账逐条升到 A 级；
2. 补齐项目书第一部分政策数字的官方出处（139 审查要点、效率 +50% 等），建参考文献表；
3. 区分"平台实测数字"与"文献引用数字"，前者可仓库复算、后者必须有出处。

**验收**：每一个对外数字都可追溯到复算命令或文献条目；无来源的数字一律不进报送版。

### 排期建议

| 顺序 | 方向 | 理由 |
