# 3D Viewer 升级实施计划

> 日期：2026-09-19
> 基线：web-ifc-viewer (That Open Engine) 已接入 Streamlit；问题卡片「定位到 3D」房间级联动已通；GlobalId 索引、postMessage 通信、Hash 路由、自绘标记框均已就绪
> 目标：从"能看 3D 模型"升级到"能在 3D 里审图"

---

## 总览

按优先级分三级，共 8 项。第 1 级是短期交付（2-3 天），第 2 级是体验质变（1 周），第 3 级是中期亮点（2 周+）。

| 级别 | 项 | 内容 | 预计工时 | 依赖 |
|---|---|---|---|---|
| **第 1 级** | 1 | 审查结果着色（违规构件染色） | 0.5 天 | 规则引擎输出 element_global_ids（可先用房间级 gids 兜底） |
| | 2 | 反向联动（3D 点击→问题列表定位） | 0.5 天 | viewer 已发 postMessage，Streamlit 侧缺接收 |
| | 3 | 楼层切换器（楼层过滤/剖切） | 0.5 天 | 已有楼层索引（floorMap） |
| **第 2 级** | 4 | 构件级精确定位 | 1.5-2 天 | 需逐条规则改输出 element_global_ids |
| | 5 | 3D 信息面板增强（尺寸/材料/规则） | 1 天 | 构件级定位完成后 |
| | 6 | 剖切/半透明/隔离三视图模式 | 1 天 | 楼层切换器 |
| **第 3 级** | 7 | AI 自然语言查询 3D 定位 | 2 天 | 构件级定位 + 审查结果结构化 |
| | 8 | 冲突问题双构件高亮 + 相机聚焦 | 1 天 | 构件级定位 |

## 第 1 级：短期交付（2-3 天，立刻看得见）

### 1. 审查结果着色（违规构件染色）

**现状**：3D 模型本色显示，看不出哪里有问题。

**做什么**：
- Python 侧：把所有违规构件的 GlobalId 列表（按严重度/学科分组）通过 URL hash 或 postMessage 传给 viewer
- Viewer 侧：模型加载完成后，对违规构件叠加染色
  - 🔴 严重违规：红色半透明覆盖 + 红色边缘高亮
  - 🟠 中等违规：橙色边缘高亮
  - ⚪ 合规：保持原色
  - 🔘 未审查构件：半透明（opacity 0.3）
- 技术实现：用 `viewer.IFC.selector.prepickIfcItemsByID` 或自绘 subset 叠加（优先用现成 API，不可靠则用自绘 mesh 方案，参考现有 `showMarker` 模式）

**验收**：FZK 模型加载后，肉眼即可分辨哪些构件违规、哪些合规；违规数量与问题列表总数一致。

---

### 2. 反向联动（3D 点击→问题列表定位）

**现状**：viewer 已在 `onclick` 时向父页面发 `elementClicked` postMessage（带 globalId、name、type），但 Streamlit 侧没接收。

**做什么**：
- 在结果页用 `st.components.v1.html` 注入一段 JS，监听 iframe 发来的 postMessage
- 收到 `elementClicked` 后，把 globalId 写入 session_state（或通过 Streamlit 组件通信机制）
- 问题列表侧：根据 globalId 匹配对应的问题卡片，自动展开并滚动到视口
- 匹配逻辑：优先按 `element_global_ids` 匹配（第 2 级完成后），兜底按房间名匹配

**验收**：在 3D 里点任意墙/门，右侧问题列表自动展开对应条目并高亮。

---

### 3. 楼层切换器（楼层过滤/剖切）

**现状**：3D 整栋楼一起显示，没有楼层过滤。

**做什么**：
- Viewer 顶部加一排楼层按钮（从 floorMap 自动生成）
- 点击某层：隐藏其他楼层的构件，只显示该层
- 提供两种模式切换：
  - **剖切模式**：显示当前层及以下（适合看整体结构）
  - **单层模式**：只显示当前层（适合看单层细节）
- 实现方式：遍历空间结构树，按楼层 expressID 收集子构件，用 `hideIfcItems` / `showAllMeshes`

**验收**：点击楼层按钮，3D 视图切换到对应楼层；与二维平面图楼层切换一致。

## 第 2 级：体验质变（约 1 周）

### 4. 构件级精确定位

**现状**：定位是"房间级"——高亮房间里所有构件，用标记框圈房间范围。

**做什么**：
- 规则引擎改造：每条违规输出 `element_global_ids: [...]`
  - 单构件规则（墙厚、门宽等）：1 个 ID
  - 冲突类规则：2+ 个 ID
  - 房间级规则（面积、疏散距离）：房间 GlobalId
- 先改高频的 5-10 条规则：
  - 建筑：门宽不足、窗高不足、房间面积不足、疏散距离超长
  - 结构：墙厚不足、柱截面不足
  - MEP：管间距不足
- Viewer 侧：定位时用构件自身几何高亮（不是房间框），相机聚焦到该构件

**改造范围**：
- `core/engine.py` 各学科规则函数
- `app.py` 问题卡片定位逻辑（优先用 element_global_ids，兜底用房间级）
- `ifc-demo/main.js` highlight 函数（增强单构件高亮效果）

**验收**：点击"门宽不足"问题 → 3D 里精确高亮那扇门，不是一整个房间都亮。

---

### 5. 3D 信息面板增强

**现状**：信息面板只有名称、IFC 类型、GlobalId。

**做什么**：
- 点击构件后，右侧（或 viewer 内浮层）显示完整信息：
  - 三轴尺寸（X/Y/Z，从 bbox 算）
  - 所属楼层
  - 材料（带 AI 归一化标注：`AI 识别: 混凝土`）
  - 触发的审查规则列表（规则 ID + 标题 + 严重度）
  - 规范条文引用
- 数据来源：
  - 几何/类型：IFC 直接读
  - 审查结果：Python 侧通过 postMessage 传一份完整的 `{gid: [issues]}` 映射
  - AI 归一化材料：从 enricher 结果取

**验收**：点任意构件，能看到"它为什么违规、违反了哪条规范"。

---

### 6. 剖切 / 半透明 / 隔离三视图模式

**现状**：只有默认全显示模式。

**做什么**：
- Viewer 顶部加视图模式切换按钮：
  - 🌐 **全景模式**（默认）：全显示
  - ✂️ **剖切模式**：只看当前楼层（以上隐藏/半透明）
  - 🎯 **隔离模式**：只看选中构件，其余半透明
- 隔离模式配合反向联动使用：点问题 → 隔离该构件 → 看得更清楚
- 剖切模式配合楼层切换器使用

**验收**：三种模式切换流畅；隔离模式下选中构件清晰突出；剖切模式与楼层切换联动。

## 第 3 级：中期亮点（2 周+）

### 7. AI 自然语言查询 3D 定位

**做什么**：
- 在 3D viewer 旁（或顶部）加一个自然语言输入框
- 用户输入："找出所有宽度不足的疏散门" / "第二层有哪些墙厚不够"
- AI 解析为结构化查询：
  ```
  { discipline: "building", rule_type: "door_width", severity: "High", floor: "2F" }
  ```
- 从审查结果里筛选匹配的违规 → 3D 高亮对应构件
- **红线**：AI 只做"自然语言 → 规则查询"的翻译，判定逻辑 100% 由确定性规则给出；查询结果可追溯到具体规则 ID

**技术方案**：
- 用 DeepSeek API，few-shot prompt 给 5-10 个示例
- 输出 JSON 格式，严格校验字段
- 失败兜底：提示"无法理解，请换一种说法"

**验收**：输入 5 种不同问法，都能正确高亮对应构件，且结果与规则引擎输出一致。

---

### 8. 冲突问题双构件高亮 + 相机聚焦

**现状**：冲突类问题（管道穿梁、梁柱碰撞）只显示文字描述。

**做什么**：
- 冲突问题的 `element_global_ids` 包含 2+ 个构件
- 点击定位 → 3D 里同时高亮 A、B 两个构件
- 用不同颜色区分：
  - 🔴 MEP 管道 / 设备：红色
  - 🔵 结构构件（梁/柱/墙）：蓝色
- 相机自动聚焦到冲突点（两个构件 bbox 的交集中心）
- 可选：显示冲突深度/体积数值

**验收**：点击"管道穿梁"问题 → 3D 里红（管）蓝（梁）两构件同时高亮，相机拉近到穿透位置。

## 风险与备选

| 风险 | 影响 | 应对 |
|---|---|---|
| web-ifc-viewer 的 subset 高亮/染色 API 不稳定 | 第 1 级着色受阻 | 参考现有 `showMarker` 自绘方案，用 three.js 直接叠透明 mesh |
| 规则引擎改造量大（每条规则都要加 element_global_ids） | 第 2 级延期 | 先改 5-10 条高频规则做 demo，其余逐步补；房间级规则可直接用房间 GlobalId |
| Streamlit iframe 通信（父→子/子→父）不稳定 | 反向联感受阻 | 兜底用 URL hash / query 参数；或用 streamlit.components.v1 自定义组件 |
| 大模型（2000+ 构件）染色性能差 | 大模型卡顿 | 分批染色 / 只染色当前楼层 / 用 instanced mesh |
| AI 自然语言查询误映射 | 第 3 级可靠性 | 输出 JSON + 严格字段校验；匹配不到规则时诚实说"找不到对应规则" |
