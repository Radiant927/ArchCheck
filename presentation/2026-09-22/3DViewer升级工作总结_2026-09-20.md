## 二、8 项功能说明

### 第 1 级

**1. 审查结果着色**
- 模型加载后，违规构件叠加半透明色框：🔴严重 / 🟠中等 / 🟡轻微 / ⚫数据缺失
- 顶部「🔴 隐藏违规」按钮切换显隐，旁边显示违规构件统计
- 数据通道：Python 写 `violations.json` → `/api/violations` → viewer 绘制

**2. 反向联动（3D → 问题列表）**
- 在 3D 里点击任意构件 → 右侧问题列表自动展开并以 🎯 标记对应房间的问题
- 点 3D 空白处取消

**3. 楼层切换器**
- viewer 顶部楼层按钮条（从模型楼层自动生成）
- 点某层 → 只显示该层（隔离）；点「全部」恢复

### 第 2 级

**4. 构件级精确定位**
- 规则引擎为**物理构件类规则**（结构 / 管道 / 风管 / 设备）输出 `element_global_ids`——点「定位到 3D」精确高亮那一个构件（如某根梁）
- **房间级规则**（门宽、疏散距离等）按「规则字段 → 构件类型」收敛：门宽不足 → 只高亮房间里的**门**，而不是整个房间

**5. 3D 信息面板增强**
- 点击构件显示：名称 / IFC 类型 / 楼层 / 三轴尺寸 / 材料（带「AI 识别」标注）/ GlobalId / **触发的审查规则列表**（按严重度排序，含规则 ID 与规范条文）
- 数据通道：`elements.json` → `/api/elements`

**6. 三视图模式**
- viewer 顶部模式条：🌐 全景 / ✂️ 剖切（当前层及以下）/ 🎯 隔离（只看定位到的构件）

### 第 3 级

**7. AI 自然语言查询 3D 定位**
- 3D viewer 上方输入框，用自然语言提问 → AI 解析为结构化条件 → 筛选确定性规则结果 → 3D 高亮
- 实测解析：`"找出所有宽度不足的门"` → 关键词「门宽」；`"二层有哪些结构问题"` → 学科=结构、楼层=二层
- **红线**：AI 只做「自然语言 → 规则映射」，判定逻辑 100% 由确定性规则给出，结果可追溯到具体规则 ID

**8. 冲突问题双构件高亮**
- 碰撞检测输出双方 GlobalId + 重叠体块
- 点碰撞条目的「定位到 3D」→ 管道**红色**、结构**蓝色**同时高亮，相机聚焦到碰撞点

## 三、关键技术实现

### 1. 双向 postMessage 通道（桥接组件）
Streamlit 主页面 ↔ 3D iframe 之间建立实时通信，**不依赖 iframe 重载**：

```
Streamlit 主页面
  ├─ 3D viewer iframe（web-ifc-viewer）
  └─ 桥接组件 iframe（自定义 Streamlit 组件，高度 0）
```

- **viewer → Python**：点击构件广播 `elementClicked` → 桥接组件 `setComponentValue` → Python 拿到 GlobalId
- **Python → viewer**：按钮回调写 `3d_cmd` → 桥接组件 `onRender` 收到参数 → 广播给兄弟 iframe → viewer 执行

关键点：桥接组件手写了 Streamlit 组件协议（`componentReady` / `setComponentValue` / `setFrameHeight`），无需 npm 依赖。

### 2. 按钮回调（避免「点两次」）
原按钮在 viewer 渲染**之后**才设置状态，导致导航慢一拍。改用 `st.button(on_click=callback)`——回调在 rerun **之前**执行，状态在脚本重跑前就绪。

### 3. 大模型兼容：viewer 端自算包围盒
Python 侧对 >600 构件的大模型**跳过 `plan_elements` 提取**（性能保护），导致没有 bbox。
解决：Python 只传**构件 GlobalId**，viewer 用 `pickIfcItemsByID` 选中后从**实际网格**算包围盒和相机目标。
- 效果：Schependomlaan（491 条问题）中 **394 条**获得精确构件定位

### 4. 定位降级链
每条问题保证有可见反馈，按优先级：
1. 构件级精确（`element_global_ids`）
2. 房间内构件（按规则字段收敛到构件类型）
3. 房间 hull 轮廓框（房间内无构件时）
4. 楼层级（`gotoFloor`）
5. 全楼级（`fitAll`：显示全楼 + 相机拉到全局）

## 四、本轮修复的 Bug

### 1. bbox 坐标轴错位（重要）
`bbox` 的实际顺序是 **`(x0, y0, x1, y1, z0, z1)`**（经实测验证：墙 bbox `[7.41, 4.01, 11.7, 4.25, 0.0, 2.5]` → x 跨 4.29m、y 跨 0.24m、z 跨 2.5m），
但代码多处按 `(x0, y0, z0, x1, y1, z1)` 解析，造成相机目标 / 标记框 / 构件尺寸全部错位。已全部修正。

### 2. 房间归属判定
墙 / 门天生坐在房间 hull 之间的**缝隙**里，用「构件中心点是否在房间内」判定会漏掉边界构件。
改为「把 hull 从质心向外放大 1.25 倍 + 中心点判定」——FZK 房间覆盖从 2 个提升到 **7 个全覆盖**（39 个构件全部归位）。

### 3. 组件加载失败
`declare_component` 的桥接 HTML 缺少 Streamlit 握手（`componentReady`），导致 "trouble loading component"。已补全协议。

### 4. 模型「消失又出现在别处」
`fitAll` 用整个 scene 算包围盒（含网格线/坐标轴），相机被拉到极远。改为只统计真实 IFC 网格。

### 5. 全楼层审查
`app.py` 里 `parse_ifc(max_floors=3, max_rooms_per_floor=6)` 只保留「房间最多的 3 层」，多层建筑漏审。
实测解析耗时与楼层上限**无关**（瓶颈在几何提取），故改为解析**全部楼层 + 全部房间**。

| 限制 | 说明 | 建议 |

| 大模型解析慢 | Schependomlaan（2265 构件）解析约 56 秒 | 排查几何提取瓶颈（逐构件 `create_shape`），考虑并行 / 缓存 |

| 房间级定位精度 | 依赖构件的房间归属算法（现用放大 hull） | 不规则房间可能出现跨房归属，可按需调放大系数 |
| 冲突检测为粗筛 | 目前是 bbox 预筛 + 点-网格确认 | 可升级为精确布尔运算 |

## 七、一句话汇报口径

> 三维 viewer 已完成三阶段升级：先是「看得见」——违规构件按严重度着色、点击问题即可在 3D 定位；再是「看得准」——精确到单个构件、能看尺寸材料与触发规则、支持全景/剖切/隔离三视图；最后是「会对话」——用自然语言提问即可在 3D 中定位问题、冲突双方构件双色高亮。全程坚守「模型负责读懂、规则负责判定、几何数字绝不改」的边界，AI 只做语义映射与解释。
