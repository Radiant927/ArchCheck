# 审查问题 ↔ 3D 模型 双向联动 工作计划

> 日期：2026-09-17
> 阶段：A2 三维可视化 · 功能迭代
> 前置基线：3D viewer 已接入平台（web-ifc-viewer + iframe）；审查问题模块已重构为可折叠卡片

---

## 一、目标

点击审查问题卡片 → 3D 模型自动定位并高亮对应构件/区域；
点击 3D 模型构件 → 审查问题列表自动滚动到对应问题卡片（双向联动）。

让审图人员"看到问题就能看到位置"，把抽象的规范条文和具体的三维构件对应起来。

---

## 二、现状分析

### 已有能力
- ✅ 3D viewer（web-ifc-viewer）已通过 iframe 嵌入 Streamlit 结果页
- ✅ 3D viewer 支持点击构件查看属性（名称、IFC 类型、GlobalId）
- ✅ 审查问题卡片已重构为可折叠样式，预留了「定位到平面图」按钮位
- ✅ issue 数据有 `floor_name`（楼层）、`location`（房间名/位置描述）、`type`（学科）
- ✅ IFC 模型有完整构件层级（IfcBuildingStorey → IfcSpace/IfcWall/...）

### 缺失环节
- ❌ issue 数据**不带 GlobalId**——无法精确关联到具体构件
- ❌ issue 数据**不带房间 GlobalId**——房间级定位也缺 ID
- ❌ 3D viewer 没有暴露给父页面的控制接口（postMessage 通信未实现）
- ❌ Streamlit iframe 和审查卡片之间没有通信链路
- ❌ web-ifc-viewer 按 GlobalId 高亮/选中的 API 未打通

### 数据链路现状
```
规则引擎 → issue { floor_name, location(房间名), type, rule_id, ... }
                                                    ↓ ???
3D viewer → 构件 { expressID, GlobalId, Name, type, ... }
```

缺口：`location`（房间名）到 GlobalId 的映射，以及构件级问题的 GlobalId 传递。

## 三、方案设计（两步走）

### 第一步：房间级定位（优先级高，工作量小，1 天）

**做什么**：
问题卡片 → 点击「定位到 3D」→ 3D viewer 自动切换到对应楼层 + 高亮对应房间 + 相机聚焦

**实现路径**：
1. **补 issue 数据**：规则引擎生成 violation 时，加上 `room_global_id`（如果是房间级规则）
   - 或不在引擎里加，在前端（app.py）根据 `location` + `floor_name` 反向查 bdata 里的房间 ID
2. **3D viewer 增加 postMessage 接口**：
   - `{type: 'gotoRoom', roomName: '...', floorName: '...'}` → 相机定位到该房间
   - `{type: 'gotoFloor', floorName: '...'}` → 切换到某层
3. **卡片按钮改造**：「定位到平面图」→「📍 定位到 3D」
   - 点击后通过 parent.postMessage 传给 iframe（注意是 Streamlit → iframe，需要组件级通信）

**技术难点**：
- Streamlit iframe 发消息给子 iframe 需要通过 `components.html` 注入脚本，或用 `st.iframe` 的 `srcDoc` 方式包裹一层
- 备选方案：按钮改成「跳转到 3D」，滚动页面到 3D 区块 + URL hash 触发定位

**验收标准**：
- 点击任意问题卡片的「定位到 3D」按钮 → 页面滚动到 3D viewer → 3D 视图切换到对应楼层 → 对应房间高亮
- 房间级规则（疏散距离、面积、房型等）全部可定位

---

### 第二步：构件级定位（优先级中，工作量中等，2-3 天）

**做什么**：
构件级规则（墙厚不够、门宽不足、管道冲突等）→ 点击定位 → 3D 中精确高亮对应构件

**实现路径**：
1. **规则引擎改造**：
   - 每条规则在生成 violation 时，带上触发违规的构件 GlobalId 列表
   - `element_global_ids: ["id1", "id2", ...]`（大多数情况 1 个，冲突类 2+ 个）
   - 需要逐条规则改，涉及 civil/eee/structural/mep/building 各学科
2. **3D viewer 增加高亮 API**：
   - `{type: 'highlight', globalIds: [...]}` → 选中对应构件 + 相机聚焦
   - 利用 web-ifc-viewer 的 `selector.pickIfcItemsByID` 或自行实现
   - 支持多选高亮（冲突问题 = A 构件 + B 构件同时高亮）
3. **反向联动（3D → 问题列表）**：
   - 在 3D 中点击构件 → postMessage 给父页面 → 问题列表筛选/高亮涉及该构件的问题
   - （可选，第二步后期做）

**改造范围**：
- `core/engine.py`：各学科规则函数，输出 `element_global_ids`
- `ifc-demo/main.js`：增加 postMessage 接收 + 高亮 API
- `app.py`：卡片按钮 + iframe 通信

**验收标准**：
- 墙厚/门宽/窗高等构件级问题，点击「定位到 3D」→ 3D 中精确高亮对应墙/门/窗
- 冲突问题，点击定位 → 两个构件同时高亮，相机聚焦到冲突点
- 3D 中点击构件 → 问题列表高亮对应条目（反向联动）

## 四、通信协议（postMessage）

### 父页面 → 3D iframe
```javascript
// 定位到房间
{ type: 'gotoRoom', roomName: '房间1', floorName: '一层' }

// 定位到楼层
{ type: 'gotoFloor', floorName: '一层' }

// 高亮构件（按 GlobalId）
{ type: 'highlight', globalIds: ['id1', 'id2'] }

// 清除高亮
{ type: 'clearHighlight' }
```

### 3D iframe → 父页面
```javascript
// 模型加载完成
{ type: 'modelLoaded', elementCount: 1234 }

// 用户点击了构件
{ type: 'elementClicked', globalId: '...', name: '...', type: 'IfcWall' }
```

## 六、风险与备选方案

| 风险 | 影响 | 应对 |
|---|---|---|
| 房间名匹配不上（模型里房间名是编号/外语） | 第一步定位失效 | 用楼层 + 房间索引兜底；或在 bdata 里做名称归一化映射 |
| web-ifc-viewer 没有按 GlobalId 选中的直接 API | 第二步高亮实现复杂 | 自己遍历 `ifcManager.getAllItemsOfType` 建 GlobalId→expressID 映射表 |
| Streamlit iframe 通信不稳定 | 双向联感受阻 | 备选：用 URL hash 传参（`#highlight=id1,id2`），viewer 初始化时读取 |
| 规则引擎改造工作量大（每条规则都要改） | 第二步延期 | 先改造最常见的 5-10 条规则做 demo，其余逐步补 |
