# 消火栓间距计算 · 工作计划

> 归属：`presentation/2026-08-26/` · 日期：2026-09-01
> 目标：从消防管几何算 hydrant_spacing_m，激活 MEP-009 规则

---

## 为什么要做

MEP-009（消火栓间距检查，阈值 30m CN / 38m SG）因缺少字段 `hydrant_spacing_m` 在 3 个样例上停在"未检查"。这是一条 High 严重度规则，从几何算出字段后能直接激活判定。

## 两阶段方案

### 阶段 A：消防管 bbox 中心近似（当前实现）

**方法：** 对每根消防管，取其 bbox 中心点（`(min+max)/2`）作为消火栓近似位置。对每根消防管，`hydrant_spacing_m` = 到最近另一根消防管中心的距离。只有一根消防管时，用管长作为间距。

**为什么要用 bbox 中心而不是端点？**
- 管道是长条形的，bbox 中心 ≈ 管段中点
- 消火栓一般接在管道上，而不是在端点
- 端点是法兰/接头位置，不是消火栓位置
- 中点到中点的距离更能反映"两个消火栓之间"的实际间距

**为什么要用"到最近另一根"而不是"沿管道拓扑"？**
- 当前提取器不读管道连接关系（IfcRelConnects），不知道哪根管接哪根
- 拓扑布点是阶段 B 的目标
- 阶段 A 用最近邻近似，已足够发现"离消防管太远"的明显违规

**诚实标注：** 规则 description 标注"由消防管 bbox 中心近似，需复核"

**为什么不从房间算到消防管（如最初计划）？**
- 规则 scope 是 pipe（管道级），不是 room（房间级）
- 消火栓间距是"相邻消火栓之间的距离"，不是"房间到消火栓的距离"
- 房间到消火栓的距离是"消火栓覆盖半径"的概念，是另一条规则

### 阶段 B：沿管道路径布点（后续升级）

读取管道连接关系（IfcRelConnects），沿消防管路径每隔 30m 取点作为消火栓位置，算覆盖半径。

- 前提：提取器补充管道连接关系读取
- 效果：更接近真实消火栓布置逻辑
- 时间：待阶段 A 完成后评估

---

## 实施步骤

1. 加 `_elem_bbox_centroid()` 函数 —— 返回 bbox 中心点
2. 在 `_pipe_data()` 里对消防管存 centroid
3. 取完管道后，遍历 fire pipes 算 hydrant_spacing_m（最近邻距离）
4. 给 MEP-009 规则加 condition_field：只对 pipe_type="fire" 判定
5. 验证：4 样例 MEP-009 从"未检查"变"判定"

---

## 验证方法

- office_3f（6 根消防管，36m 长）→ MEP-009 应触发判定，看间距是否 ≤30m
- Duplex_MEP（0 消防管）→ 规则被 condition 过滤掉，不产生覆盖噪声
- Schependomlaan（0 消防管）→ 同上
- FZK_Haus（0 管道）→ 同上
